## 先说人话：把仓库压缩，工人照常工作
大模型 Decode 常像这样：
1. 从显存搬来一大批权重；
2. 只为当前少量 token 做计算；
3. 再为下一个 token 重复搬运。

如果计算单元等着权重到达，瓶颈就是显存带宽。Weight-only INT4 的思路是：
- 把仓库里的权重压成 4 bit；
- 激活仍保留 FP16/BF16；
- Kernel 读取压缩权重；
- 在计算附近反量化；
- 完成高精度激活参与的矩阵乘。

像把家具拆成平板运输，送到施工现场再快速展开。运输量减少了，但“展开家具”也有成本。能否变快取决于展开是否融合得足够好。
## Weight-only 到底量化了什么
对线性层：
\[Y=XW\]
Weight-only INT4 保存的是：
\[W_q,\ s,\ 可能还有\ z\]
激活 \(X\) 通常仍是 FP16 或 BF16。逻辑计算可以写成：
\[Y\approx X\cdot\operatorname{dequant}(W_q,s,z)\]
高性能 Kernel 不会先把整个 \(W\) 写回显存。它通常在 tile 级别：
1. 读取打包的 INT4；
2. 解包 nibble；
3. 读取 group scale；
4. 在寄存器或共享内存中转换；
5. 送入矩阵乘流水线；
6. 以更高精度累加。

这类“边读边解”的融合是性能关键。
## 为什么选择 INT4
FP16 每个权重占 16 bit。理想情况下，INT4 原始权重只占其四分之一。但真实 checkpoint 还包含：
- scale；
- 可选 zero-point；
- 元数据；
- 对齐 padding；
- 未量化层；
- tokenizer 和配置文件。

所以整个目录不会严格缩小到四分之一。运行时显存还包括：
- KV Cache；
- CUDA graph；
- workspace；
- 通信 buffer；
- 激活；
- 引擎元数据。

因此模型权重压缩比不能直接等同于服务显存压缩比。
## INT4 的表示与打包
4 bit 只有 16 个编码。常见有符号范围可以抽象为：
```text
[-8, 7]
```
某些对称实现使用不同边界约定。两个 4-bit 值可打包进一个字节：
```text
高 4 bit | 低 4 bit
```
但格式还必须约定：
- nibble 顺序；
- signed/unsigned 解释；
- scale dtype；
- zero-point 是否存在；
- group 沿哪个轴；
- 权重矩阵是否转置；
- tile 重排方式。

“都是 INT4”不代表二进制布局兼容。模型格式、加载器和 Kernel 必须说同一种语言。
## Group-wise 量化
设一组权重为 \(w_1,\ldots,w_G\)。对称量化可写作：
\[s=\frac{\max_i|w_i|}{7}\]
\[q_i=\operatorname{clip}( \operatorname{round}(w_i/s),-8,7)\]
\[\hat{w}_i=sq_i\]
group size \(G\) 是重要超参数。较小 group：
- 更贴合局部分布；
- 通常降低重建误差；
- scale 数量更多；
- 元数据占比更高；
- Kernel 处理更复杂。

较大 group：
- 压缩更整齐；
- scale 开销更少；
- 更容易高效向量化；
- 不同范围权重共用刻度，误差可能更大。

工程上常见的 group size 不是数学常数。只能选择量化工具和目标 Kernel 共同支持的值。
## 手算一个 INT4 group
假设一组权重：
```text
[-1.0, -0.4, 0.2, 0.9]
```
使用对称范围 `[-7, 7]` 便于手算。scale：
\[s=1.0/7\approx0.1429\]
量化结果：
```text
[-7, -3, 1, 6]
```
反量化：
```text
[-1.000, -0.429, 0.143, 0.857]
```
误差：
```text
[0.000, 0.029, 0.057, 0.043]
```
如果组里混入 `8.0`，scale 会变成约 `1.143`。其余小权重可能大量变成 0。这说明：
- group 内离群值很危险；
- 缩小 group 可隔离部分离群值；
- 算法也可以识别并保护重要权重。

GPTQ 与 AWQ 就从不同角度处理这个问题。
## GPTQ：不仅看权重误差
### 直觉
量化一列权重后会产生误差。如果知道后续哪些方向更敏感，就可以调整尚未量化的权重，补偿已经产生的误差。
像切木板时前一刀偏了，后续切割会主动修正，而不是每一刀互不相干。
### 二阶信息
设权重 \(W\in\mathbb R^{m\times d}\)，一层的 \(n\) 个校准输入按列组成
\(X\in\mathbb R^{d\times n}\)，局部重建目标常写成：
\[\min_{\widehat{W}} \|WX-\widehat{W}X\|_F^2\]
它不是单纯最小化：
\[\|W-\widehat{W}\|_F^2\]
输入相关的二阶结构可由近似 Hessian 表达。
GPTQ 基于 Optimal Brain Quantization 思路，逐列量化并利用逆 Hessian 信息更新剩余权重。直观上：
- 经常被激活放大的方向更重要；
- 误差应按输入分布加权；
- 已量化列的误差可由未量化列补偿。

## 问题驱动：相同权重 MSE，为什么输出误差不同
对某一行权重 \(w\in\mathbb R^{1\times d}\) 和校准输入 \(X\)，量化前后的层输出差为：

\[
\Delta y=(w-\hat w)X
\]

平方误差：

\[
\|\Delta y\|_2^2
=(w-\hat w)XX^\top(w-\hat w)^\top
\]

令：

\[
H=2XX^\top
\]

则局部二次损失可写成：

\[
\Delta\mathcal L
=\frac12(w-\hat w)H(w-\hat w)^\top
\]

若两个输入方向出现频率或相关性不同，\(H\) 就不是单位矩阵。因此最小化
\(\|w-\hat w\|_2^2\) 与最小化层输出误差不是同一问题。GPTQ 的核心不是“使用 Hessian”这个标签，
而是利用这个二次结构，在固定某个量化误差后调整仍为浮点的权重。

## 从约束优化推导 OBS 补偿
准备量化第 \(q\) 个权重，把它从 \(w_q\) 固定到网格点 \(\hat w_q\)。定义误差：

\[
\varepsilon_q=w_q-\hat w_q
\]

把整行权重的修正以列向量 \(\delta\in\mathbb R^d\) 表示，并要求第 \(q\) 维恰好完成该替换：

\[
e_q^\top\delta=-\varepsilon_q
\]

目标是最小化二次损失：

\[
\min_\delta\frac12\delta^\top H\delta
\quad\text{s.t.}\quad
e_q^\top\delta=-\varepsilon_q
\]

拉格朗日函数：

\[
\mathcal J(\delta,\lambda)
=\frac12\delta^\top H\delta
+\lambda(e_q^\top\delta+\varepsilon_q)
\]

一阶条件：

\[
H\delta+\lambda e_q=0
\]

\[
\delta=-\lambda H^{-1}e_q
\]

代入约束：

\[
-\lambda e_q^\top H^{-1}e_q=-\varepsilon_q
\]

\[
\lambda=\frac{\varepsilon_q}{[H^{-1}]_{qq}}
\]

得到 Optimal Brain Surgeon/OBQ 形式的最优补偿：

\[
\delta
=-\frac{w_q-\hat w_q}{[H^{-1}]_{qq}}
(H^{-1})_{:,q}
\]

对应最小损失增量：

\[
\Delta\mathcal L_q
=\frac{(w_q-\hat w_q)^2}
{2[H^{-1}]_{qq}}
\]

这说明候选权重不能只按舍入距离排序。相同的 \(|w_q-\hat w_q|\)，若
\([H^{-1}]_{qq}\) 不同，敏感度也不同。

量化完第 \(q\) 维后，从自由变量集合删除它。剩余逆 Hessian 可用 Schur complement/一次高斯消元更新：

\[
H_{-q}^{-1}
=\left(
H^{-1}
-\frac{H^{-1}_{:,q}H^{-1}_{q,:}}
{[H^{-1}]_{qq}}
\right)_{-q}
\]

原始逐权重 OBQ 很昂贵。GPTQ 的关键工程化包括：对一列的多行权重并行、按 block 更新、任意固定顺序近似，以及用带 dampening 的 Cholesky 形式稳定地预计算所需逆 Hessian 信息。

## 二维手算：相关输入怎样补偿
令：

\[
H^{-1}=
\begin{bmatrix}
2&1\\
1&2
\end{bmatrix},
\qquad
w=[0.9,\ 0.4]
\]

假设第 0 维量化到 \(\hat w_0=1.0\)，则：

\[
\varepsilon_0=w_0-\hat w_0=-0.1
\]

\[
\delta
=-\frac{-0.1}{2}
\begin{bmatrix}2\\1\end{bmatrix}
=
\begin{bmatrix}0.1\\0.05\end{bmatrix}
\]

第一维从 0.9 变为 1.0，满足量化约束；尚未量化的第二维从 0.4 调整到 0.45，补偿相关输入方向上的输出误差。损失增量为：

\[
\Delta\mathcal L_0
=\frac{(-0.1)^2}{2\times2}=0.0025
\]

若误把 Hessian 当作对角阵，第二维不会被更新，就失去了相关性补偿。

### 为什么要 dampening
校准样本少于 hidden dimension 或输入方向高度相关时，\(XX^\top\) 可能奇异或病态。实际使用：

\[
H_\lambda=2XX^\top+\lambda I
\]

提高可逆性。damp 太小可能导致 Cholesky 失败或补偿系数爆炸；太大则让
\(H_\lambda\) 更接近对角占优，削弱输入相关结构。它是数值稳定与二阶信息保真之间的超参数。

## GPTQ block 算法在做什么
对权重矩阵 `W[out, in]`，GPTQ 常沿输入列处理。一个 block 内：

```text
for column j in block:
    Q[:, j] = quantize(W[:, j])
    E[:, j] = (W[:, j] - Q[:, j]) / Hinv_factor[j, j]
    用 E[:, j] 更新 block 内尚未量化列
block 完成后:
    一次矩阵乘把累计误差传播到后续所有列
```

`blocksize` 是离线量化的计算/内存参数，不等于推理时 `group_size`。前者控制误差更新分块，
后者控制多少权重共享量化 scale。模型卡若只写一个 `128`，必须确认它指哪一个。

`act-order`/`desc_act` 通常按输入通道的重要性重排量化顺序，以优先处理高激活方向；推理时若需要
保留 `g_idx` 间接索引，可能与某些固定连续 group 的 Kernel 冲突。现代格式可能在导出阶段重排权重来消除运行时间接访问，但这依赖具体 converter。

### 工程参数
常见 GPTQ 产物会涉及：
- bit width；
- group size；
- symmetric/asymmetric；
- activation ordering（常见名 `desc_act` 或 act-order）；
- dampening；
- block size；
- calibration dataset。

字段名称和支持组合随工具变化。不要只复制模型卡中的一个 `--quantization gptq`，还要读取 checkpoint 的量化配置。
### GPTQ 的 trade-off
优点：
- 无需完整再训练；
- 利用输入统计，通常优于朴素舍入；
- 生态成熟，已有多种推理实现。

代价：
- 离线量化计算较重；
- 对校准样本敏感；
- 不同 GPTQ 格式并不总兼容；
- act-order 等特性可能限制 Kernel 选择。
## AWQ：保护真正重要的权重
### 直觉
权重绝对值大，不一定代表它对输出最重要。一个权重是否重要，还取决于对应激活通道是否经常很大。AWQ 的观察是：
> 只保护很少一部分显著权重，就能明显减小量化造成的输出误差。它使用激活统计识别显著通道，再通过通道缩放寻找更适合量化的权重表示。
### 缩放思路
仍考虑：
\[Y=XW\]
可以插入通道缩放：
\[Y=(X\operatorname{diag}(s)^{-1}) (\operatorname{diag}(s)W)\]
AWQ 搜索有利于权重量化的缩放，使重要权重在 INT4 网格中得到更好保护。与 SmoothQuant 的形式看起来相似，但目标不同：
- SmoothQuant 重点是让激活更容易做 W8A8；
- AWQ 重点是提高 Weight-only 低比特量化质量。

不要把两者因为“都有缩放”就视为同一算法。

## AWQ 的 activation-aware 目标
对 `nn.Linear` 布局 \(W\in\mathbb R^{O\times I}\)，令输入通道缩放
\(s\in\mathbb R^I_{>0}\)。浮点恒等式是：

\[
XW^\top
=(X\operatorname{diag}(s)^{-1})
(W\operatorname{diag}(s))^\top
\]

只量化缩放后的权重：

\[
\hat W(s)=Q(W\operatorname{diag}(s))
\operatorname{diag}(s)^{-1}
\]

则输出重建目标可写为：

\[
s^*=\arg\min_s
\|XW^\top-X\hat W(s)^\top\|_2^2
\]

缩放本身不改变浮点函数，但改变了共享 INT4 scale 前的权重相对幅值。AWQ 使用激活统计识别对输出更重要的通道，并搜索缩放强度。常见直觉参数化是让
\(s_j\) 随激活幅值 \(\mathbb E|X_j|\) 的幂增长，再通过网格搜索选择指数；具体公式、搜索网格和 clipping 由实现版本决定。

重要性来自输出影响而非单看 \(|W_{o,j}|\)。例如：

```text
channel A: weight=0.05, typical |activation|=100 -> contribution≈5
channel B: weight=1.00, typical |activation|=0.1 -> contribution≈0.1
```

只按权重绝对值会认为 B 更重要，activation-aware 统计则会保护 A。

### 一个缩放手算
一组权重：

```text
important channel weights: [0.12, -0.10]
other weights:             [1.00, -0.80]
```

若四个值共享对称 INT4 scale \(1/7\)，第一组近似编码为 `[1, -1]`。假设把重要输入通道放大
4 倍，缩放后权重为：

```text
[0.48, -0.40, 1.00, -0.80]
```

仍使用 \(1/7\) 附近的 scale 时，重要权重得到约 `[3, -3]` 的更多网格分辨率。在线上，输入对应通道除以 4，浮点函数不变。代价是缩放后可能抬高组内 amax，或让别的值 clip；因此 AWQ 要搜索，而不是无条件放大所有高激活通道。

## INT4 group、scale 与真实存储开销
假设权重 `W[O, I]` 沿输入维按 \(G\) 分组，且 \(I\) 可被 \(G\) 整除。对称、每组一个 FP16 scale、无 zero-point 时：

\[
\text{data bytes}=\frac{OI}{2}
\]

\[
\text{scale bytes}=2O\frac{I}{G}
\]

平均每权重 bit 数：

\[
b_{\text{eff}}
=4+\frac{16}{G}
\]

例如 \(G=128\) 时公式给出 \(4.125\) bit/weight；这只是权重与 FP16 scale 的逻辑数据，不含 padding、索引、量化配置和未量化层。

若每组还保存 4-bit zero-point：

\[
b_{\text{eff}}
=4+\frac{16}{G}+\frac{4}{G}
\]

实际格式常为对齐把 zero-point 打包到更宽整数，不能直接按 4 bit 估算文件大小。

## 数据布局：从逻辑矩阵到 Marlin tile
最朴素的 nibble 打包：

```python
packed = q_even | (q_odd << 4)
```

只解决存储，不解决 Tensor Core 供数。高性能 Kernel 通常还会离线重排：

- K 维相邻值怎样组成 32-bit/128-bit vector load；
- 哪些 nibble 分配给同一 warp lane；
- scale 如何与 K-group 对齐；
- N 维输出通道如何匹配 MMA tile；
- Tensor Parallel shard 后是否需要重新 repack。

因此常见三层 layout：

```text
logical W[O, I]
  -> quantized codes + scales in interchange/checkpoint layout
  -> runtime repack/preprocess
  -> kernel-specific tiled layout
```

加载耗时可能包含第三步。若 runtime 每次启动都 repack，应把启动时间与额外内存计入运维评估。

### 可运行的打包/解包验证

```python
import torch

def pack_u4(q):
    assert q.dtype == torch.uint8
    assert q.numel() % 2 == 0
    q = q.flatten()
    assert bool(torch.all(q <= 15))
    return q[0::2] | (q[1::2] << 4)

def unpack_u4(p):
    out = torch.empty(p.numel() * 2, dtype=torch.uint8)
    out[0::2] = p & 0x0F
    out[1::2] = (p >> 4) & 0x0F
    return out

q_signed = torch.tensor([-8, -3, 0, 7], dtype=torch.int16)
q_storage = (q_signed + 8).to(torch.uint8)
packed = pack_u4(q_storage)
restored = unpack_u4(packed).to(torch.int16) - 8
print("packed bytes:", packed.tolist())
print("restored:", restored.tolist())
torch.testing.assert_close(restored, q_signed)
```

这只能验证 nibble 协议；它不是 GPTQ/AWQ/Marlin checkpoint converter。

## Marlin 的执行路径
Marlin 类 weight-only Kernel 的目标是让压缩权重节省的 DRAM 流量大于解包与反量化成本。概念流水线：

```text
global memory:
  coalesced load packed INT4 weight + group scales
register/shared memory:
  bit extract / permutation
  convert INT4 codes to half/bfloat representation
  apply group scales
tensor core pipeline:
  high-precision activation tile x dequantized weight tile
  higher-precision accumulation
epilogue:
  reduce split-K partials / bias / output store
```

关键是软件流水：当一个 tile 在 Tensor Core 计算时，下一 tile 的压缩权重和 scale 已在加载/解包。
如果矩阵太小、K/N 不对齐、group 变化频繁或 occupancy 太低，解包无法被隐藏。

Marlin 论文和仓库针对特定 NVIDIA 架构、格式与 shape 优化。vLLM 中出现 “Marlin” 名称也不表示
任意 GPTQ/AWQ 参数组合都走同一个 Kernel；runtime 可能有普通 AWQ/GPTQ Kernel、Marlin 变体或回退。

## 可复现实验：比较 RTN 与 Hessian 感知补偿
下面的 CPU 小实验只演示“量化一维后更新另一维”，不是完整 GPTQ。

```python
import torch

torch.set_default_dtype(torch.float64)

# 两个高度相关的输入方向，行是特征、列是样本。
X = torch.tensor([
    [1.0, 2.0, 3.0, 4.0],
    [0.9, 2.1, 2.9, 4.2],
])
w = torch.tensor([0.9, 0.4])
wq0 = torch.tensor(1.0)

H = 2 * X @ X.T + 1e-6 * torch.eye(2)
Hinv = torch.linalg.inv(H)

w_rtn = w.clone()
w_rtn[0] = wq0

error0 = w[0] - wq0
delta = -(error0 / Hinv[0, 0]) * Hinv[:, 0]
w_obs = w + delta

loss = lambda candidate: ((candidate - w) @ X).square().sum()
print("H:\n", H)
print("RTN:", w_rtn.tolist(), "loss:", loss(w_rtn).item())
print("OBS:", w_obs.tolist(), "loss:", loss(w_obs).item())
assert abs(w_obs[0] - wq0) < 1e-9
assert loss(w_obs) <= loss(w_rtn)
```

再把 `X` 两行改成近似正交，补偿幅度会变化。这比只观察 weight MSE 更能说明 GPTQ 的目标。

### 层级 fake-quant 对照

```python
import torch

torch.manual_seed(11)
X = torch.randn(256, 64)
W = torch.randn(32, 64) * 0.1

def int4_group_qdq(w, group_size=16):
    assert w.shape[1] % group_size == 0
    wg = w.reshape(w.shape[0], -1, group_size)
    scale = wg.abs().amax(dim=-1, keepdim=True).clamp_min(1e-12) / 7
    q = torch.clamp(torch.round(wg / scale), -7, 7)
    return (q * scale).reshape_as(w)

Wq = int4_group_qdq(W)
weight_mse = (Wq - W).square().mean()
output_rel_l2 = ((X @ Wq.T) - (X @ W.T)).norm() / (X @ W.T).norm()
print("weight_mse:", weight_mse.item())
print("output_rel_l2:", output_rel_l2.item())
```

改变 `X` 某些通道的方差，即使 `Wq` 不变，weight MSE 不变而 output relative-L2 会变化。

## 质量与性能测量
量化算法离线评测至少分三层：

1. **权重层**：按层/按 group 的 MSE、饱和率、scale 分布；
2. **层输出层**：校准外样本上的 relative-L2、cosine、最差层；
3. **端到端层**：NLL/perplexity、任务与业务指标、长尾样本。

GPTQ 与 AWQ 的公平对照必须使用同一 base revision、同一 bit/group、同一 calibration/test split。
社区 checkpoint 若无法确认校准数据与 recipe，只能作为“具体 checkpoint”比较，不能归纳成算法结论。

性能则拆成：

- checkpoint size 与加载/repack 时间；
- 静态权重显存；
- 代表性 GEMM shape 的 Kernel 时间；
- Prefill TTFT 与 Decode TPOT；
- 相同 SLO 下的最大稳定并发。

Profiler 里确认 packed-weight load、反量化融合和实际 Kernel；不要把 `nvidia-smi` utilization 当成 Marlin 证据。

## 决策边界与更完整的失败模式
- **Hessian 奇异**：样本不足或通道相关，Cholesky 失败；增加 damp 不是自动正确，需重测质量。
- **校准域失配**：GPTQ 的 \(XX^\top\) 和 AWQ 的 activation importance 都会偏。
- **act-order 与 group 冲突**：逻辑重排破坏连续 group，runtime 需要索引或 repack。
- **scale dtype 被忽略**：FP16 scale 自身误差在极端小 group 上也可能可见。
- **K 维不能整除 group**：converter padding 后 base model shape 与 runtime 元数据不一致。
- **TP 切开 group**：单卡产物直接多卡加载，scale shard 错位。
- **BF16 activation 被转成 FP16**：Kernel 支持表中的 activation dtype 不匹配，范围或性能发生变化。
- **Prefill 退化**：weight-only 解包路径在大 GEMM 上不如原生 FP8/W8A8。

选择建议：

- 模型放不下或 Decode 明显权重带宽受限：先比较成熟 INT4 checkpoint；
- 有可靠校准数据、可接受较长离线量化：GPTQ 值得作为候选；
- 希望较轻量的 activation-aware PTQ 且目标引擎 AWQ/Marlin 路径成熟：比较 AWQ；
- Prefill 是主瓶颈且硬件有原生低精度 MMA：同时比较 W8A8/FP8，不预设 INT4 胜出；
- Kernel 不支持目标 group/zero-point/act-order：换兼容 recipe，不能只靠 CLI 强制。

## 版本与硬件边界
GPTQ 公式以 ICLR 2023 论文为依据，AWQ 以 MLSys 2024 论文为依据，Marlin 以论文及官方仓库为依据。
算法名不定义唯一 checkpoint 格式。

截至 **2026-08-13**，本文核对的 vLLM **v0.27.1** 官方量化页把 GPTQ、AWQ 与 Marlin 分列，并按 GPU 架构给出兼容矩阵；
该矩阵明确会演进。上线时固定 vLLM commit/版本，并从当前源码或启动日志确认 quantization method
实际选择的 Kernel。旧 GPU、非 NVIDIA 后端和 Blackwell 上的支持不能由一张过期表外推。
### AWQ 的 trade-off
优点：
- 训练后完成；
- 利用激活感知重要性；
- 有成熟的 INT4 推理生态；
- 通常适合权重带宽受限场景。

代价：
- 仍需要代表性校准数据；
- 搜索配置与导出格式要匹配引擎；
- 某些 shape 或硬件上未必走最佳 Kernel；
- 极端任务仍可能出现质量回退。
## GPTQ 与 AWQ 怎样选
两者都属于 Weight-only PTQ，但优化思路不同。GPTQ 更强调：
- 二阶误差补偿；
- 逐列或分块量化；
- 层输出重建。

AWQ 更强调：
- 激活感知；
- 显著权重保护；
- 通道缩放搜索。

不要只用算法名称选型。应比较具体产物：
- 同一基础模型 revision；
- 同一 bit 与 group size；
- 同一目标 GPU；
- 同一引擎版本；
- 同一质量集；
- 同一性能压测。

社区 checkpoint 的校准数据与参数可能不同，算法名相同也不能保证质量相同。
## Marlin Kernel：压缩如何变成速度
Marlin 是面向低比特权重、高精度激活矩阵乘的高性能 Kernel 路线。它解决的不只是数学计算，还包括：
- INT4 权重打包和重排；
- 合并全局内存读取；
- 高效反量化；
- scale 应用；
- Tensor Core 友好的数据供给；
- 不同线程块之间的工作划分。

可以把它理解为一条流水线：
```text
压缩权重读取
  -> 解包与转换
  -> scale 融合
  -> Tensor Core 计算
  -> 高精度累加
```
如果每个阶段配合不好，省下的显存带宽会被解包、同步或低占用率抵消。Marlin 不是所有 INT4 checkpoint 的通用开关。是否可用取决于：
- GPU 架构；
- 量化格式；
- bit width；
- group size；
- 是否有 zero-point；
- act-order；
- 矩阵 shape；
- vLLM 版本。

应以当前 vLLM 官方支持矩阵和启动日志为准。
## Prefill 与 Decode 的差异
Prefill 一次处理许多 token，矩阵乘规模较大。这时可能更偏计算受限，原生 W8A8/FP8 等路线也很有吸引力。
Decode 每步 token 数少，但每层都要读取权重。这时常更偏权重带宽受限，Weight-only INT4 的压缩价值更明显。
不过高并发 Continuous Batching 会改变矩阵 shape。所以不能笼统地说：
> INT4 只对 Decode 有用。
必须按线上 batch 分布分别测试 Prefill 和 Decode 指标。
## Tensor Parallel 的约束
权重矩阵会沿某个维度切到多个 rank。切分后需要检查：
- 局部维度是否满足 Kernel 对齐；
- group 是否跨越 shard 边界；
- scale 是否正确切分；
- 打包布局是否需要重新排列；
- 通信是否成为新瓶颈。

量化减少单卡权重，但不会自动减少所有 collective 通信。某些并行策略中传输的是激活，其 dtype 可能仍为 FP16/BF16。

python -c "import vllm; print(vllm.__version__)"

```
然后阅读 checkpoint 的：
- `config.json`；
- 量化配置文件；
- 模型卡；
- 基础模型 revision；
- 推荐 runtime。

典型服务命令形态是：

```

## 常见失败模式
### 格式不兼容
加载器理解的 packing 与 checkpoint 不一致。结果可能是直接报错，也可能是输出异常。
### group size 不支持
算法允许某个 group size，Kernel 却没有对应实现。
### act-order 限制
GPTQ 的列重排可能需要额外索引，影响特定 Kernel 的兼容性或性能。
### 小 batch 没跑满
省下权重带宽，但 Kernel 启动和反量化开销占比太高。
### 质量平均值掩盖长尾
总体得分接近，关键子任务却明显回退。
### 把磁盘压缩当作运行时压缩
某些 checkpoint 在加载时会展开到更高精度。需要看实际显存和 Kernel，不能只看文件后缀。
## 本节小结
Weight-only INT4 主要压缩固定权重，激活通常保持 FP16/BF16。
它尤其适合权重搬运占主要成本的场景，但性能依赖融合反量化 Kernel。GPTQ 用二阶信息和误差补偿改善量化，AWQ 用激活统计保护重要权重。
算法决定精度上限，打包格式决定能否加载，Marlin 等 Kernel 决定压缩能否转化为速度。
选型时要同时看质量、显存、shape、GPU 和服务 SLO。
