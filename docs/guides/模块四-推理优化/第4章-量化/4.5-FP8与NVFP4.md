## 先说人话：整数尺与科学计数法
INT8 像一把刻度间距固定的尺子。无论数值大还是小，相邻格子的距离由同一个 scale 决定。浮点数更像科学计数法：
```text
有效数字 × 2^指数
```
它能用指数覆盖很大的范围，但有效数字位数有限。对神经网络而言，有些张量既包含很小的值，也会偶尔出现很大的值。
低比特浮点保留指数，可以比同位宽定点整数更自然地覆盖动态范围。代价是：
- 编码规则更复杂；有效精度有限；不同格式不兼容；必须依赖硬件和 Kernel 支持。

FP8 是 8-bit 浮点家族。NVFP4 与 MXFP4 是 4-bit 路线，但二者不是同一个名字的两种写法。
## 浮点格式由什么组成
典型二进制浮点包含：
- 1 位符号；若干指数位；若干尾数位。

概念上：
\[x=(-1)^s\times m\times 2^e\]
指数位越多：
- 动态范围通常越大；能覆盖更大或更小的数量级。

尾数位越多：
- 相邻可表示数更密；局部相对精度通常更好。

总位宽固定时，指数与尾数在“范围”和“精细度”之间竞争。此外还要定义：
- exponent bias；subnormal；infinity；NaN；是否 finite-only；舍入模式；饱和规则。

因此只知道 `E4M3` 还不够，要知道框架采用的具体变体。
## FP8 的 E4M3 与 E5M2
### E4M3
名称表示：
- 1 位符号；4 位指数；3 位尾数。

直觉上，它在 FP8 家族中偏向更多有效精度。常用于前向计算中的权重和激活，但具体用途由框架策略决定。
### E5M2
名称表示：
- 1 位符号；5 位指数；2 位尾数。

它牺牲一位尾数，换取更大指数范围。训练中梯度动态范围较大时，E5M2 可能更有吸引力。推理并不要求“一律 E4M3”。
应由模型、校准方法、硬件指令和推理引擎共同决定。
## FP8 为什么仍需要 scale
“有指数”不等于“无需缩放”。设原张量为 \(x\)，量化可概念化为：
\[q=\operatorname{cast}_{FP8}(x/s)\]
\[\hat{x}=s\cdot\operatorname{cast}_{high}(q)\]
scale 的目标是让数据更充分地落入 FP8 有效范围。如果直接 cast：
- 大值可能溢出或饱和；小值可能下溢；有效编码利用不足。

scale 可以采用：
- per-tensor；per-channel；per-token；per-block；动态 scale；延迟更新的历史 scale。

粒度越细通常越适应局部分布，但元数据和运行时开销越大。
## FP8 手算直觉
不展开某个具体 FP8 变体的位级编码，先看缩放作用。假设张量绝对最大值为：
\[a_{\max}=1000\]
假设目标格式希望把最大幅值映射到某个有限上界 \(F\)。可选择：
\[s=a_{\max}/F\]
于是最大值缩放后约为：
\[1000/s=F\]
其余数值也按相同比例缩放。这个过程与整数 min-max scale 类似，区别是量化网格不是等间距。浮点数的相邻间距随指数区间变化。
所以 FP8 的误差更适合看相对误差与溢出，不能完全套用 INT8 的“半个固定 scale”结论。
## Hopper 上的 FP8
NVIDIA Hopper 架构引入面向 FP8 的 Transformer Engine 和 Tensor Core 能力。
“Hopper 支持 FP8”包含多层含义：
1. 硬件指令支持 FP8 矩阵乘；
2. CUDA/cuBLASLt 等库提供路径；
3. 框架能生成合适布局与 scale；
4. 推理引擎能加载 checkpoint；
5. 模型 shape 能命中高性能 Kernel。

缺少任何一层，都可能出现：
- 无法加载；dtype 转换；高精度回退；性能不及预期。

FP8 GEMM 常以更高精度累加。输入 dtype、累加 dtype 和输出 dtype不应混为一谈。
## FP8 量化的常见方式
### 静态 FP8
使用校准集确定 scale。优点：
- 推理路径可预测；少做运行时归约；更容易融合。

风险：
- 分布漂移时可能饱和；校准集必须代表线上输入。
### 动态 FP8
根据当前激活计算 scale。优点：
- 适应输入范围；对激活变化更稳健。

代价：
- 需要最大值归约；增加量化 Kernel；可能影响 CUDA graph；小矩阵时开销占比高。
### Block FP8
每个小块共享 scale。它在精度和元数据之间折中，也便于某些 Kernel 以 tile 为单位处理。
具体 block shape 必须与导出格式和 Kernel 一致。
## FP8 与 INT8 的差别
二者都是 8 bit，但数值网格不同。INT8 配合单个 scale：
- 网格等间距；加减和 zero-point 语义直接；整数矩阵乘生态成熟。

FP8：
- 网格随指数变化；更自然覆盖多数量级；对动态范围大的激活有优势；强依赖新硬件原生支持。

精度不能仅由位宽判断。同一数据上，INT8 per-channel 可能优于粗粒度 FP8，也可能相反。需要比较具体 scale 粒度和 Kernel。
## 从 8 bit 再到 4 bit
FP4 只有 4 个 bit。如果单个数值独立承担符号、指数和尾数，可表示能力非常有限。工程上的关键办法是：
> 让一小块数值共享一个额外 scale。
每个 4-bit 元素只表示局部小范围，共享 scale 负责把这个局部范围搬到真实数量级。
这类设计常称为 microscaling 或 block scaling。其成本包括：
- 共享 scale 元数据；block 边界；scale 计算；特殊打包布局；对应 Tensor Core 数据通路。
## MXFP4 是什么
MX 是 Open Compute Project 的 Microscaling Formats 规范。其核心思想是：
- 一组低精度元素共享 scale；scale 使用规范定义的格式；元素使用 MX 规定的低精度类型；block size 和语义由规范约束。

MXFP4 是该标准体系中的 4-bit 浮点方案。谈论 MXFP4 时，应明确：
- 使用哪个版本的 OCP 规范；block size；scale 格式；元素格式；实现是否完全遵循规范。

不要把所有“带 block scale 的 FP4”都称为 MXFP4。
## NVFP4 是什么
NVFP4 是 NVIDIA 面向 Blackwell Tensor Core 的 FP4 数据格式与量化路线。公开资料描述的关键点包括：
- 4-bit 浮点元素；细粒度 block scaling；额外的张量级缩放；与 Blackwell 硬件数据通路配合。

它和 MXFP4 都使用共享缩放思想，但 block 组织与 scale 设计并不相同。因此：
```text
NVFP4 != MXFP4
```
checkpoint 标注为 NVFP4，不能假设 MXFP4 Kernel 可直接读取，反之亦然。
应以 NVIDIA 官方格式说明、TensorRT Model Optimizer 和目标推理引擎文档为准。
## 双层 scale 的直觉
假设张量被切成很多 block。每个 block 有局部 scale \(s_b\)，整个张量还有全局 scale \(s_t\)。
概念性反量化可以写成：
\[\hat{x}_{b,i}=q_{b,i}\times s_b\times s_t\]
局部 scale 负责：
- 适应每个小块的范围；减少块内量化误差。

全局 scale 负责：
- 调整张量整体范围；配合特定 scale 编码的表示能力。

这只是帮助理解的抽象公式。具体 NVFP4 scale 编码、block 大小和处理顺序应以官方规范与实现为准。
## 为什么 Blackwell 很关键
低比特格式只有在硬件能高效消费时，才可能把压缩变成计算吞吐。Blackwell Tensor Core 提供面向 FP4 的硬件能力。
在更早 GPU 上：
- checkpoint 也许能被读取；但可能先转换到更高精度；或根本没有兼容 Kernel；不应期待同样的 FP4 计算收益。

所以 NVFP4 不是一个“对任意 CUDA GPU 都更快”的格式。硬件代际是选型的首要条件。
## Kernel 看到的不只是 dtype
高性能 FP8/FP4 Kernel 还关心：
- 权重布局；scale 布局；block size；tile shape；K 维对齐；M/N 维规模；累加类型；epilogue 融合；Tensor Parallel shard 后的局部 shape。

模型配置写了 `fp8` 或 `nvfp4`，只是声明意图。运行日志、profiler 和硬件计数器才说明实际走了哪条路径。
## Transformer 中哪些张量量化
“FP8 模型”可能有多种含义：
- 权重 FP8，激活高精度；权重与激活 FP8；Linear 使用 FP8，其他算子高精度；KV Cache 也使用 FP8；checkpoint 以 FP8 保存但加载后转换；动态激活 FP8。

必须明确：
1. 权重存储 dtype；
2. 激活输入 dtype；
3. GEMM 输入 dtype；
4. 累加 dtype；
5. 输出 dtype；
6. KV Cache dtype。

否则不同方案无法公平比较。
## 校准与敏感层
FP8 比 FP16 范围和精度都更有限。NVFP4/MXFP4 又进一步压缩。常见工程策略包括：
- 使用代表性校准集；对不同层独立 scale；对敏感层保留 BF16/FP16；对输出头使用更高精度；对少数离群通道使用更细粒度；通过量化工具搜索配置。

哪些层敏感与模型有关。不能无证据地规定“第一层和最后一层永不量化”。应让质量评测决定保留策略。
## vLLM 与模型格式
先检查当前版本：
```bash
python -c "import vllm; print(vllm.__version__)"
vllm serve --help
```
再查看官方量化支持页面，确认目标组合：
- vLLM 版本；GPU 架构；量化方法；checkpoint 格式；Tensor Parallel；Attention backend。

服务命令通常从模型目录开始：
```bash
vllm serve /path/to/model
```
有些格式可由量化配置自动识别，有些版本需要显式参数。不要把文档中某个版本的命令当成永久稳定接口。
## 性能验证
至少建立同源模型对照：
- BF16/FP16；FP8；NVFP4 或 MXFP4（硬件和引擎支持时）。

记录环境：
- GPU 型号；驱动；CUDA；vLLM；模型 revision；量化工具及版本；scale 粒度；并行配置。

分别测量：
- Prefill TTFT；Decode TPOT；吞吐；并发容量；峰值显存；P95/P99；功耗（若业务关心）。

FP4 的理论算力数字不能代替端到端服务压测。
## 质量验证
低比特浮点的误差与整数不同，但质量门槛相同。建议包括：
- 基础任务集；业务评测集；数学与代码；多语言；长上下文；结构化输出；多模态（若模型支持）。

除平均值外，报告最差子集和失败样本类型。还要检查：
- NaN/Inf；重复输出；退化为高频 token；置信度异常；长输出后质量漂移。
## Trade-off 总览
### FP8
优势：
- 相比 FP16/BF16 减少存储和带宽；保留指数，适合较大动态范围；Hopper 及更新硬件有原生计算路径。

代价：
- 需要 scale 管理；质量依赖粒度和校准；旧硬件收益有限；格式变体与工具链复杂。
### NVFP4
优势：
- 更激进的权重/激活压缩潜力；面向 Blackwell FP4 Tensor Core；细粒度 scaling 改善 4-bit 表示能力。

代价：
- 对硬件代际要求高；scale 元数据与布局复杂；生态和兼容组合仍在演进；比 FP8 更需要严格质量验证。
### MXFP4
优势：
- OCP microscaling 标准体系；通过共享 scale 支撑 4-bit 元素。

代价：
- 不能与 NVFP4 混用概念；实现仍取决于硬件与软件支持；block 和 scale 规则必须精确匹配。
## 常见误区
### FP8 等于 INT8
位宽相同，编码网格、硬件指令和 scale 语义不同。
### FP4 checkpoint 在所有 GPU 上都快
没有原生硬件与 Kernel，可能转换或回退。
### MXFP4 就是 NVFP4
二者共享 microscaling 直觉，但格式定义不同。
### 量化后所有算子都是低精度
Norm、Softmax、部分 Linear 和累加可能仍保持高精度。
### 理论 TFLOPS 就是线上吞吐
服务还受访存、调度、Attention、通信和 batch shape 限制。
## 本节小结
FP8 用指数和尾数在 8 bit 内平衡范围与精度。E4M3 偏向尾数精度，E5M2 偏向指数范围，但具体变体和用途要看实现。
scale 仍是 FP8 工程的核心。FP4 通过 block/microscaling 扩展有限编码的可用范围。
MXFP4 属于 OCP MX 规范，NVFP4 是 NVIDIA 面向 Blackwell 的格式与量化路线，两者不能互换。
最终选择必须从 GPU 原生能力出发，再核对 checkpoint、Kernel、质量和端到端 SLO。
