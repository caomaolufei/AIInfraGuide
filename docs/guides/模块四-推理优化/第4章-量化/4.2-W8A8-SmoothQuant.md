## 先说人话：把难搬的行李换个箱子
W8A8 的含义是：
- Weight 用 8 bit；
- Activation 也用 8 bit；
- 矩阵乘尽量走 INT8 路径；
- 累加通常使用更高精度。

权重在部署前已经固定，可以逐层仔细选择刻度。激活却由用户输入实时产生，而且经常出现少量特别大的值。想象 127 个普通行李箱中混进一根超长鱼竿。
如果所有行李共用一个货架刻度，鱼竿会迫使每一格都变得很大。普通行李之间的细小差别因此被抹掉。SmoothQuant 的直觉是：
> 不切掉鱼竿，而是把一部分“长度负担”转移到另一个更容易安排的箱子。术语上，它用数学等价的通道缩放，平滑激活离群值，并把对应缩放吸收到权重中。
## 为什么激活比权重难量化
线性层写作：
\[Y=XW\]
为方便描述，假设 \(X\) 的最后一维与 \(W\) 的输入通道对应。权重有几个有利条件：
- 数值固定；
- 可以离线统计；
- 可以按输出通道或 group 使用不同 scale；
- 可以花较多时间做误差优化。

激活则不同：
- 随请求变化；
- 不同 token 分布不同；
- 某些通道长期出现离群值；
- 静态 scale 必须覆盖校准分布；
- 动态 scale 又会增加运行时开销。

在大语言模型中，激活离群值常集中在少数通道，而不是均匀随机分布。这为 SmoothQuant 提供了机会：可以按通道处理这些“难量化通道”。
## 直接 W8A8 的误差来源
假设某通道的激活为：
```text
[0.2, -0.4, 0.1, 31.0]
```
若使用对称 INT8，scale 约为：
\[s_X=31/127\approx0.244\]
此时 `0.1` 量化为 0，`0.2` 量化为 1。主体的小值只剩下很少的整数格子。如果把 31 截断，小值会更精确，但离群值误差可能破坏后续输出。
动态 per-token scale 能缓解部分问题，却需要每次推理统计范围，也未必符合目标 INT8 Kernel 的输入形式。
## SmoothQuant 的等价变换
原始线性层：
\[Y=XW\]
选择一个按输入通道定义的正向量 \(s\)。插入恒等变换：
\[Y=(X\operatorname{diag}(s)^{-1}) (\operatorname{diag}(s)W)\]
定义：
\[\widetilde{X}=X\operatorname{diag}(s)^{-1}\]
\[\widetilde{W}=\operatorname{diag}(s)W\]
则：
\[Y=\widetilde{X}\widetilde{W}\]
在无限精度下，前后计算完全等价。如果某激活通道特别大，选择较大的 \(s_j\)：
- 激活通道 \(X_j\) 被除小；
- 权重对应输入通道被乘大；
- 激活更容易用 INT8 表示；
- 量化难度被迁移到固定权重。

权重通常比激活更容易按细粒度量化，所以这个交换可能降低总误差。
## 平滑参数 alpha
SmoothQuant 论文给出的常见构造是：
\[s_j= \frac{ \max(|X_j|)^\alpha }{ \max(|W_j|)^{1-\alpha} }\]
这里：
- \(j\) 是输入通道；
- \(\max(|X_j|)\) 来自校准激活；
- \(\max(|W_j|)\) 来自对应权重；
- \(\alpha\in[0,1]\) 控制迁移强度。

直觉上：
- \(\alpha\) 小：少动激活，权重压力较小；
- \(\alpha\) 大：更强地压平激活，权重范围被放大；
- 中间值：在两边量化难度之间折中。

alpha 不是越大越好。它需要结合：
- 模型结构；
- 校准数据；
- 激活与权重量化粒度；
- 目标任务质量；
- 实际 Kernel。

论文中的推荐值是实验起点，不是所有模型的固定答案。
## 一个简化手算
假设某输入通道：
\[\max|X_j|=16\]
对应权重通道：
\[\max|W_j|=1\]
取：
\[\alpha=0.5\]
则：
\[s_j=\frac{16^{0.5}}{1^{0.5}}=4\]
平滑后：
\[\max|\widetilde{X}_j|=16/4=4\]
\[\max|\widetilde{W}_j|=1\times4=4\]
原来范围差异为 16 对 1，现在变为 4 对 4。注意这只是直觉示例。真实层里有许多通道，权重和激活还会按不同粒度量化。最终误差不能只靠最大值判断。
## 变换怎样进入模型
SmoothQuant 不应在每次推理时显式执行：
```text
X / s
```
否则会增加额外 Kernel 和访存。常见做法是把激活侧缩放折叠到前置算子，把权重侧缩放离线吸收到线性层权重。
以 LayerNorm 后接 Linear 为例，缩放可以结合模型结构做离线变换或算子融合。具体折叠位置依赖：
- Pre-LN 或 Post-LN；
- RMSNorm 或 LayerNorm；
- QKV、门控 MLP 的分支结构；
- 残差连接；
- 框架导出规则。

不能看到一个 Linear 就独立修改。必须保证所有共享输入和分支保持数学等价。
## W8A8 的计算路径
理想路径大致是：
```text
FP16/BF16 输入
  -> 激活量化为 INT8
  -> INT8 x INT8 Tensor Core GEMM
  -> INT32 或更高精度累加
  -> scale/偏置/激活函数融合
  -> FP16/BF16 输出
```
实际 dtype 和融合顺序由 Kernel 决定。W8A8 的性能潜力来自两部分：
1. 权重和激活访存减少；
2. GPU 的 INT8 矩阵乘吞吐能力。

但也增加了：
- 激活量化；
- scale 读取与应用；
- 可能的格式转换；
- 不支持算子的高精度回退。

因此端到端收益取决于算子覆盖率。
## 静态、动态与混合策略
### 静态激活量化
scale 来自校准集。优点：
- 推理时无需范围归约；
- 便于融合；
- 更适合追求稳定 Kernel 路径。

风险：
- 线上超出校准范围时会 clip；
- Prompt 分布变化会影响质量。

SmoothQuant 主要帮助静态 INT8 量化落地。
### 动态激活量化
按 token 或当前张量计算 scale。优点：
- 适应当前输入；
- 减少固定范围不匹配。

代价：
- 运行时量化与归约开销；
- scale 粒度受 Kernel 限制；
- 图捕获与融合更复杂。
### 混合精度
并非所有算子都必须 INT8。常见保留高精度的部分可能包括：
- embedding；
- normalization；
- softmax；
- 某些输出层；
- 对误差敏感的模块。

实际保留范围应由工具、格式和评测决定，不能照搬另一模型的排除列表。
## 校准数据怎样准备
校准的目标不是训练模型，而是观察激活范围。建议覆盖：
- 真实 Prompt 模板；
- 主流语言；
- 代码、数学或领域文本；
- 不同输入长度；
- system prompt；
- 业务中常见的特殊 token。

校准数据过窄会产生两个问题：
1. scale 不能覆盖线上输入；
2. 选出的 alpha 只适合局部分布。

需要固定随机种子并记录：
- 样本来源；
- 样本数；
- 截断长度；
- tokenizer；
- 模型 revision；
- alpha；
- 量化粒度与排除层。
## 工程流程
下面是工具无关流程，不是某个量化库的可执行 API：
```python
# 伪代码：字段名由实际量化工具决定
model = load_fp_model(model_id, revision=revision)
stats = collect_activation_max(
    model,
    calibration_samples,
)
scales = choose_smooth_scales(
    activation_stats=stats,
    weights=model.weights,
    alpha=0.5,
)
fold_scales_into_model(model, scales)
quantize_weights_and_activations(
    model,
    weight_dtype="int8",
    activation_dtype="int8",
)
export_checkpoint(model, output_dir)
```
真正执行时，应使用量化工具的官方示例与版本文档。导出后还要确认：
- checkpoint 中保存了什么 scale；
- vLLM 能否识别量化配置；
- 目标 GPU 是否支持相应实现；
- 日志中是否选择预期 Kernel。
## 硬件与 Kernel 约束
### GPU 代际
不同 GPU 对 INT8 Tensor Core 的支持不同。即使硬件支持 INT8，推理框架也要有适配该架构的 Kernel。
不要根据“CUDA 可用”推断“W8A8 高效”。
### 维度对齐
Tensor Core Kernel 通常要求矩阵维度满足一定倍数。Tensor Parallel 切分可能改变局部维度。
模型原维度对齐，不代表每个 rank 上仍对齐。
### 算子覆盖
如果只有部分 Linear 使用 INT8，其他算子仍可能成为瓶颈。应通过 profiler 或引擎日志确认：
- INT8 GEMM 占比；
- 量化/反量化 Kernel 开销；
- dtype cast；
- 回退 Kernel；
- 通信时间。
### Shape 与并发
Prefill 常有较大的矩阵，更容易利用矩阵乘吞吐。Decode 在小 batch 下矩阵更“瘦”，可能更受权重带宽和 Kernel 启动开销影响。
因此 W8A8 对 Prefill 和 Decode 的收益可能不同。
## Trade-off
### 相比 FP16/BF16
潜在优势：
- 权重显存更小；
- 激活带宽更低；
- 可利用 INT8 Tensor Core；
- 大矩阵计算可能更高效。

潜在代价：
- 需要校准；
- 激活量化有额外开销；
- 离群值和分布漂移带来质量风险；
- 兼容性不如高精度路径普遍。
### 相比 Weight-only INT4
W8A8：
- 位宽更高，通常更容易保持质量；
- 同时量化激活，有原生整数计算潜力；
- 权重压缩不如 INT4。

INT4 Weight-only：
- 权重更省显存和带宽；
- 激活常保留 FP16/BF16；
- 依赖融合反量化 Kernel；
- 对 Decode 的权重带宽瓶颈可能更有吸引力。

没有统一赢家。要看硬件、模型、阶段和 SLO。
## 如何验证 SmoothQuant
至少准备三组：
1. 原始 FP16/BF16 基线；
2. 直接 W8A8（若工具支持）；
3. SmoothQuant W8A8。

质量对比应包括：
- 校准分布内任务；
- 分布外但合法的输入；
- 长上下文；
- 数学、代码和结构化输出；
- 业务关键样本。

性能对比应保持：
- 相同 GPU；
- 相同 vLLM 版本；
- 相同并行策略；
- 相同请求集合；
- 相同采样参数；
- 相同预热；
- 相同并发扫描。

不要用单条 Prompt 的墙钟时间下结论。
## 常见失败模式
### alpha 过大
激活变平滑，但权重某些通道被放大，导致权重量化误差上升。
### 校准集失配
离线统计没有覆盖线上激活，固定 scale 发生严重 clip。
### 分支折叠错误
缩放只应用到部分共享分支，破坏数学等价性。
### 格式能导出但引擎不支持
量化工具与服务引擎对配置字段、打包布局或 scale 粒度理解不一致。
### Kernel 回退
模型可以生成，但实际没有走 INT8 高性能路径。这时质量可能正常，性能却不符合预期。
## 本节小结
W8A8 同时量化权重与激活。它的核心难点是输入相关的激活，尤其是少数通道中的离群值。SmoothQuant 插入按通道的等价缩放：
- 激活除以 \(s\)；
- 权重乘以 \(s\)；
- 原始浮点函数不变；
- 量化误差在两侧重新分配。

alpha 控制迁移强度，校准数据决定统计是否可信，而真实收益最终由 INT8 Kernel 覆盖和 workload 决定。
