## 先说人话：把难搬的行李换个箱子
W8A8 的含义是：
- Weight 用 8 bit；
- Activation 也用 8 bit；
- 矩阵乘尽量走 INT8 路径；
- 累加通常使用更高精度。

权重在部署前已经固定，可以逐层仔细选择刻度。激活却由用户输入实时产生，而且经常出现少量特别大的值。想象 127 个普通行李箱中混进一根超长鱼竿。
如果所有行李共用一个货架刻度，鱼竿会迫使每一格都变得很大。普通行李之间的细小差别因此被抹掉。SmoothQuant 的直觉是：
> 不切掉鱼竿，而是把一部分“长度负担”转移到另一个更容易安排的箱子。术语上，它用数学等价的通道缩放，平滑激活离群值，并把对应缩放吸收到权重中。
## 为什么激活比权重难量化
线性层写作：
\[Y=XW\]
为方便描述，假设 \(X\) 的最后一维与 \(W\) 的输入通道对应。权重有几个有利条件：
- 数值固定；
- 可以离线统计；
- 可以按输出通道或 group 使用不同 scale；
- 可以花较多时间做误差优化。

激活则不同：
- 随请求变化；
- 不同 token 分布不同；
- 某些通道长期出现离群值；
- 静态 scale 必须覆盖校准分布；
- 动态 scale 又会增加运行时开销。

在大语言模型中，激活离群值常集中在少数通道，而不是均匀随机分布。这为 SmoothQuant 提供了机会：可以按通道处理这些“难量化通道”。
## 直接 W8A8 的误差来源
假设某通道的激活为：
```text
[0.2, -0.4, 0.1, 31.0]
```
若使用对称 INT8，scale 约为：
\[s_X=31/127\approx0.244\]
此时 `0.1` 量化为 0，`0.2` 量化为 1。主体的小值只剩下很少的整数格子。如果把 31 截断，小值会更精确，但离群值误差可能破坏后续输出。
动态 per-token scale 能缓解部分问题，却需要每次推理统计范围，也未必符合目标 INT8 Kernel 的输入形式。
## SmoothQuant 的等价变换
原始线性层：
\[Y=XW\]
选择一个按输入通道定义的正向量 \(s\)。插入恒等变换：
\[Y=(X\operatorname{diag}(s)^{-1}) (\operatorname{diag}(s)W)\]
定义：
\[\widetilde{X}=X\operatorname{diag}(s)^{-1}\]
\[\widetilde{W}=\operatorname{diag}(s)W\]
则：
\[Y=\widetilde{X}\widetilde{W}\]
在无限精度下，前后计算完全等价。如果某激活通道特别大，选择较大的 \(s_j\)：
- 激活通道 \(X_j\) 被除小；
- 权重对应输入通道被乘大；
- 激活更容易用 INT8 表示；
- 量化难度被迁移到固定权重。

权重通常比激活更容易按细粒度量化，所以这个交换可能降低总误差。
## 平滑参数 alpha
SmoothQuant 论文给出的常见构造是：
\[s_j= \frac{ \max(|X_j|)^\alpha }{ \max(|W_j|)^{1-\alpha} }\]
这里：
- \(j\) 是输入通道；
- \(\max(|X_j|)\) 来自校准激活；
- \(\max(|W_j|)\) 来自对应权重；
- \(\alpha\in[0,1]\) 控制迁移强度。

直觉上：
- \(\alpha\) 小：少动激活，权重压力较小；
- \(\alpha\) 大：更强地压平激活，权重范围被放大；
- 中间值：在两边量化难度之间折中。

alpha 不是越大越好。它需要结合：
- 模型结构；
- 校准数据；
- 激活与权重量化粒度；
- 目标任务质量；
- 实际 Kernel。

论文中的推荐值是实验起点，不是所有模型的固定答案。
## 一个简化手算
假设某输入通道：
\[\max|X_j|=16\]
对应权重通道：
\[\max|W_j|=1\]
取：
\[\alpha=0.5\]
则：
\[s_j=\frac{16^{0.5}}{1^{0.5}}=4\]
平滑后：
\[\max|\widetilde{X}_j|=16/4=4\]
\[\max|\widetilde{W}_j|=1\times4=4\]
原来范围差异为 16 对 1，现在变为 4 对 4。注意这只是直觉示例。真实层里有许多通道，权重和激活还会按不同粒度量化。最终误差不能只靠最大值判断。

## 问题驱动：为什么不直接删掉离群通道
SmoothQuant 要解决的不是“最大值不好看”，而是以下冲突：

- 静态 INT8 activation scale 必须在离线确定；
- 少数输入通道在许多 token 上持续产生大幅值；
- per-tensor/per-token INT8 Kernel 的 scale 比 per-element 便宜；
- 直接 clipping 可能删掉模型依赖的信号；
- 运行时为每个通道做动态量化又可能不符合高效 Kernel 布局。

所以真正的问题是：

> 能否保持浮点函数完全不变，却改变量化前两个操作数的动态范围？

SmoothQuant 的答案是可以，但只在缩放轴、分支和折叠位置都正确时成立。

## 从平衡目标推导 alpha 公式
记校准集上输入通道 \(j\) 的最大绝对激活为：

\[
A_j=\max_{\text{tokens}}|X_j|
\]

对应权重输入通道的最大绝对值为：

\[
W_j=\max_{\text{outputs}}|W_{j,:}|
\]

采用缩放 \(s_j>0\) 后，两侧范围变为：

\[
\widetilde A_j=A_j/s_j,\qquad
\widetilde W_j=s_jW_j
\]

若要求两侧最大值完全相等：

\[
\frac{A_j}{s_j}=s_jW_j
\]

得到：

\[
s_j=\sqrt{\frac{A_j}{W_j}}
\]

这正是 \(\alpha=1/2\) 的情况。更一般地，用 \(\alpha\) 控制迁移比例：

\[
s_j=\frac{A_j^\alpha}{W_j^{1-\alpha}}
\]

代回：

\[
\widetilde A_j=A_j^{1-\alpha}W_j^{1-\alpha}
=(A_jW_j)^{1-\alpha}
\]

\[
\widetilde W_j=A_j^\alpha W_j^\alpha
=(A_jW_j)^\alpha
\]

因此：

- \(\alpha=0\)：\(\widetilde W_j=1\)，权重通道范围被归一化，激活侧承担乘积范围；
- \(\alpha=1/2\)：两侧范围平衡；
- \(\alpha=1\)：\(\widetilde A_j=1\)，激活通道范围被归一化，权重侧承担乘积范围。

这里的“1”来自归一化后的范围表达，不表示权重元素都变成 1。实际实现还必须处理
\(A_j=0\) 或 \(W_j=0\)，通常对统计量加很小的正下界：

\[
s_j=\frac{\max(A_j,\epsilon)^\alpha}
{\max(W_j,\epsilon)^{1-\alpha}}
\]

\(\epsilon\) 的数值和 dtype 属于实现细节，应记录工具版本，不能在不同导出器间假设一致。

## 两通道手算：等价不等于量化误差相同
设：

\[
X=
\begin{bmatrix}
16 & 1\\
-8 & 2
\end{bmatrix},
\quad
W=
\begin{bmatrix}
1 & -0.5\\
0.25 & 2
\end{bmatrix}
\]

这里采用 \(Y=XW\)，所以 \(W\) 的行是输入通道。两个输入通道的统计为：

\[
A=[16,2],\qquad W_{\max}=[1,2]
\]

取 \(\alpha=0.5\)：

\[
s_0=\sqrt{16/1}=4,\qquad s_1=\sqrt{2/2}=1
\]

\[
\widetilde X=X\operatorname{diag}([1/4,1])
=
\begin{bmatrix}
4&1\\
-2&2
\end{bmatrix}
\]

\[
\widetilde W=\operatorname{diag}([4,1])W
=
\begin{bmatrix}
4&-2\\
0.25&2
\end{bmatrix}
\]

原始第一行输出：

\[
[16,1]W=[16.25,-6]
\]

平滑后：

\[
[4,1]\widetilde W=[16.25,-6]
\]

浮点结果严格一致。变化发生在之后的 QDQ：原始激活最大值 16，平滑后最大值 4；权重最大值则从 2 变为 4。是否值得，取决于激活和权重各自使用的粒度。

若权重按 output-channel 或更细 group 量化，放大的第一输入通道可能被独立 scale 吸收；若整个权重共用一个粗 scale，\(\alpha=0.5\) 也可能让其他权重更难表示。

## 张量轴与模型折叠
设框架中的线性层为：

```text
x:        [batch, tokens, hidden]
weight:   [out_features, hidden]  # PyTorch nn.Linear
y = x @ weight.T
smooth:   [hidden]
```

则逻辑变换应是：

```text
x_tilde      = x / smooth[None, None, :]
weight_tilde = weight * smooth[None, :]
```

也就是对权重的**列**缩放。论文写作 \(XW\) 时，权重通常写成 `[hidden, out]`，此时看起来是行缩放。两者只是矩阵存储约定不同，却是最常见的实现错误之一。

若前一算子为 RMSNorm：

\[
h=\operatorname{RMSNorm}(u;\gamma),\qquad y=hW^\top
\]

希望消去运行时 `h / s`，可在结构允许时把比例折进 norm 参数和后续权重：

\[
\widetilde\gamma=\gamma/s,\qquad
\widetilde W=W\operatorname{diag}(s)
\]

但如果同一个 \(h\) 同时进入 Q、K、V 或 gate/up 多个分支，所有消费者都必须乘同一个对应
\(s\)。如果残差路径也直接使用 \(h\)，则不能只改一条 Linear 分支。折叠工具需要基于计算图处理，而不是逐个模块名替换。

## 离群值统计：max 只是起点
对每个输入通道收集：

\[
A_j=\max_{n,t}|X_{n,t,j}|
\]

是论文与工具常见的统计，但它有三个边界：

1. 样本数增加时 max 单调不减，极少数异常输入会长期影响 scale；
2. 截断长度改变会改变 token 位置与激活分布；
3. chat template、system prompt 和语言域都会改变通道幅值。

可同时记录通道的 P99.9、最大值出现次数和饱和率候选，但不要擅自把论文 max 改成百分位后仍称为同一 recipe。若修改统计，应把它作为独立实验变量。

校准切分建议：

```text
calibration split: 收集 A_j、搜索 alpha
selection split:   从 alpha 候选中选质量最好的配置
test split:        只做最终报告
```

同一数据既搜索 alpha 又汇报质量会产生选择偏差。

## 可复现实验：验证恒等变换与 alpha 扫描
以下脚本只做 PyTorch fake quant，可在 CPU 运行。它有意构造一个离群输入通道，并分别测量浮点等价性和 QDQ 输出误差。

```python
import torch

torch.manual_seed(7)

def sym_qdq_per_tensor(x, bits=8):
    qmax = 2 ** (bits - 1) - 1
    amax = x.abs().max().clamp_min(torch.finfo(x.dtype).tiny)
    scale = amax / qmax
    q = torch.clamp(torch.round(x / scale), -qmax, qmax)
    return q * scale

def sym_qdq_weight_per_out(w, bits=8):
    # nn.Linear layout: [out, in]
    qmax = 2 ** (bits - 1) - 1
    scale = w.abs().amax(dim=1, keepdim=True)
    scale = scale.clamp_min(torch.finfo(w.dtype).tiny) / qmax
    q = torch.clamp(torch.round(w / scale), -qmax, qmax)
    return q * scale

tokens, hidden, out = 512, 16, 12
x = torch.randn(tokens, hidden)
x[:, 3] *= 24.0                    # 稳定的离群通道
w = torch.randn(out, hidden) * 0.2

a = x.abs().amax(dim=0)
w_in = w.abs().amax(dim=0)
y_ref = x @ w.T

for alpha in (0.0, 0.25, 0.5, 0.75, 1.0):
    smooth = a.clamp_min(1e-12).pow(alpha)
    smooth /= w_in.clamp_min(1e-12).pow(1 - alpha)
    x_s = x / smooth
    w_s = w * smooth[None, :]

    # 先验证未量化恒等性。
    torch.testing.assert_close(x @ w.T, x_s @ w_s.T, rtol=1e-5, atol=1e-5)

    x_hat = sym_qdq_per_tensor(x_s)
    w_hat = sym_qdq_weight_per_out(w_s)
    y_hat = x_hat @ w_hat.T
    rel = (y_hat - y_ref).norm() / y_ref.norm()
    sat_proxy = x_s.abs().max().item()
    print(f"alpha={alpha:.2f} rel_l2={rel:.6f} activation_amax={sat_proxy:.3f}")
```

不要预设 `0.5` 必赢。这个结果由随机矩阵、离群模式和量化粒度共同决定。把权重改为 per-tensor、把激活改为 per-token，最优 alpha 可能变化。

### 验证校准分布漂移

```python
# 沿用上面的 w 和 calibration a
x_ood = torch.randn(tokens, hidden)
x_ood[:, 3] *= 24.0
x_ood[:, 9] *= 40.0               # 校准时未出现的新离群通道

alpha = 0.5
smooth = a.clamp_min(1e-12).pow(alpha)
smooth /= w_in.clamp_min(1e-12).pow(1 - alpha)

calib_range = (x / smooth).abs().max()
ood_scaled = x_ood / smooth
clipped = (ood_scaled.abs() > calib_range).float().mean()
print("OOD clipped fraction under static range:", clipped.item())
```

这段实验直接回答“alpha 已确定，为什么线上仍会退化”：平滑比例只反映校准时看到的通道结构。

## W8A8 GEMM 的整数推导
先考虑对称量化：

\[
X\approx s_xQ_x,\qquad W\approx s_wQ_w
\]

则：

\[
Y=XW\approx s_xs_w(Q_xQ_w)
\]

\(Q_xQ_w\) 的乘积通常累加到 INT32，再乘 scale 写回高精度。若 \(s_x\) 是 per-token，
\(s_w\) 是 per-output-channel，则输出位置 \((t,o)\) 使用：

\[
\hat{Y}_{t,o}=s^x_t s^w_o
\sum_k Q^x_{t,k}Q^w_{k,o}
\]

scale 外积形状是 `[tokens, out_features]`，但不需要真的物化；epilogue 可按行、列广播。

若两侧都有 zero-point：

\[
\sum_k(Q^x_k-z_x)(Q^w_k-z_w)
\]

展开为：

\[
\sum_kQ^x_kQ^w_k
-z_w\sum_kQ^x_k
-z_x\sum_kQ^w_k
+Kz_xz_w
\]

后三项增加归约、预计算或 epilogue 复杂度。这解释了为什么高性能 W8A8 常偏好对称编码，而不是因为非对称量化在数学上“不正确”。

### 溢出边界
最坏情况下，一个 INT8 乘积幅值约为 \(127^2=16129\)。长度 \(K\) 的点积上界随 \(K\) 线性增长：

\[
|\mathrm{acc}|\le K\cdot16129
\]

真实 Kernel 的分块累加、输入范围和 INT32 上界决定是否安全。不能仅凭“累加为 INT32”推断任意
\(K\) 都不会溢出；框架可能限制 shape、缩放输入或使用不同累加策略。

## Kernel 执行路径与数据布局
一个静态 SmoothQuant W8A8 checkpoint 可能保存：

```text
INT8 weight tiles
per-output-channel weight scales
activation static scale 或量化配置
已折叠的 norm / linear 参数
布局与 scheme 元数据
```

运行时典型路径：

```text
BF16 activation
  -> 使用静态或动态 scale 转 INT8
  -> 按 Tensor Core 要求重排/加载 A tile
INT8 packed weight
  -> 按 K/N tile 合并加载
INT8 x INT8 MMA
  -> INT32 partial sums
  -> 乘 sx * sw，融合 bias
  -> BF16/FP16 output
```

SmoothQuant 本身不定义 checkpoint 二进制布局，也不提供 Kernel。算法、量化工具与引擎是三层契约：

- 算法决定如何平滑和选 scale；
- 导出器决定权重与 scale 如何保存；
- runtime 决定何种 shape 命中何种 GEMM。

## 质量与性能测量
### alpha 搜索报告
每个候选至少记录：

- 平滑前后 activation/weight 的按通道 amax 分布；
- activation 饱和比例；
- 层输出 relative-L2、cosine 与最差层；
- validation NLL/任务指标；
- 量化配置、排除层和校准数据哈希。

不要用校准集上的 layer MSE 作为最终质量。

### Kernel 证据
对代表性 Prefill 与 Decode shape 分别 profile：

- activation quantization/reduction 用时；
- INT8 GEMM Kernel 名称和总占比；
- cast、transpose、layout conversion；
- 高精度 GEMM fallback；
- Tensor Parallel collective。

若 W8A8 仅减少 checkpoint 体积而 GEMM 回退，报告应明确写“存储压缩有效，计算加速未命中”。

### 公平服务对照
比较 BF16、直接 W8A8 和 SmoothQuant W8A8 时固定：

```text
model/tokenizer revision
vLLM image and attention backend
TP/PP and max_model_len
KV dtype and gpu_memory_utilization
request trace and arrival process
sampling parameters
warmup and CUDA graph policy
```

分别报告 TTFT、TPOT，因为 activation W8A8 对大 Prefill GEMM 与小 Decode GEMM 的收益不同。

## 失败模式与决策边界
- **\(A_j\) 或 \(W_j\) 为零**：未加下界会生成 0、Inf 或 NaN scale。
- **轴写反**：数值 shape 可广播，但权重缩放了 output channel，恒等关系失效。
- **共享输入只改一个分支**：Q 改了，K/V 未改，或 gate/up 缩放不一致。
- **平滑后溢出**：alpha 太大使权重通道在 FP16 中放大到不可接受范围。
- **校准泄漏**：用测试集选 alpha，报告过于乐观。
- **静态范围漂移**：线上新语言、模板或长序列引入新离群通道。
- **动态 W8A8 开销被忽略**：每 token amax reduction 在小 Decode shape 上占主导。
- **以算法名推断 Kernel**：SmoothQuant 产物能加载，但布局未命中 INT8 GEMM。

选择边界：

- 激活离群通道稳定、可获得代表性校准数据、目标 INT8 Kernel 成熟：SmoothQuant 值得比较；
- 输入域快速变化且静态 clipping 明显：先比较动态 per-token W8A8 或 FP8；
- 主要问题是 Decode 权重带宽：INT4 weight-only 可能比 W8A8 更直接；
- 目标是长上下文 KV 容量：SmoothQuant 不是对应工具；
- 无法证明缩放折叠的浮点等价性：停止导出，不进入质量压测。

## 版本与硬件边界
本文公式对应 SmoothQuant（ICML 2023）论文的离线平滑思想；具体 API 不属于论文标准。
截至 **2026-08-13**，本文核对的 vLLM **v0.27.1** 官方 INT8 W8A8 页面以 LLM Compressor recipe 为主要路径，
并将支持范围绑定到具体 GPU 架构与 vLLM 版本；官方支持矩阵会变化。

INT8 Tensor Core 的存在不等于任意 INT8 checkpoint 可执行。Blackwell 等新架构上的具体支持状态尤其应以
**已安装 vLLM 版本**的支持矩阵为准，不要从 Hopper 的结果外推。发布记录中至少固定：

```text
GPU name + compute capability
driver/CUDA/PyTorch/vLLM/LLM Compressor version
model revision + recipe
weight/activation scheme and alpha
actual selected kernel
```
## 变换怎样进入模型
SmoothQuant 不应在每次推理时显式执行：
```text
X / s
```
否则会增加额外 Kernel 和访存。常见做法是把激活侧缩放折叠到前置算子，把权重侧缩放离线吸收到线性层权重。
以 LayerNorm 后接 Linear 为例，缩放可以结合模型结构做离线变换或算子融合。具体折叠位置依赖：
- Pre-LN 或 Post-LN；
- RMSNorm 或 LayerNorm；
- QKV、门控 MLP 的分支结构；
- 残差连接；
- 框架导出规则。

不能看到一个 Linear 就独立修改。必须保证所有共享输入和分支保持数学等价。
## W8A8 的计算路径
理想路径大致是：
```text
FP16/BF16 输入
  -> 激活量化为 INT8
  -> INT8 x INT8 Tensor Core GEMM
  -> INT32 或更高精度累加
  -> scale/偏置/激活函数融合
  -> FP16/BF16 输出
```
实际 dtype 和融合顺序由 Kernel 决定。W8A8 的性能潜力来自两部分：
1. 权重和激活访存减少；
2. GPU 的 INT8 矩阵乘吞吐能力。

但也增加了：
- 激活量化；
- scale 读取与应用；
- 可能的格式转换；
- 不支持算子的高精度回退。

因此端到端收益取决于算子覆盖率。
## 静态、动态与混合策略
### 静态激活量化
scale 来自校准集。优点：
- 推理时无需范围归约；
- 便于融合；
- 更适合追求稳定 Kernel 路径。

风险：
- 线上超出校准范围时会 clip；
- Prompt 分布变化会影响质量。

SmoothQuant 原论文重点解决静态 INT8 激活的离群值问题。现代工具也可能把平滑与动态
per-token activation quantization 组合；例如本文核对的 vLLM v0.27.1 LLM Compressor
W8A8 recipe 就属于具体工具方案，不能只凭 `SmoothQuant` 名称推断 activation scale 是静态还是动态。
### 动态激活量化
按 token 或当前张量计算 scale。优点：
- 适应当前输入；
- 减少固定范围不匹配。

代价：
- 运行时量化与归约开销；
- scale 粒度受 Kernel 限制；
- 图捕获与融合更复杂。
### 混合精度
并非所有算子都必须 INT8。常见保留高精度的部分可能包括：
- embedding；
- normalization；
- softmax；
- 某些输出层；
- 对误差敏感的模块。

实际保留范围应由工具、格式和评测决定，不能照搬另一模型的排除列表。
## 校准数据怎样准备
校准的目标不是训练模型，而是观察激活范围。建议覆盖：
- 真实 Prompt 模板；
- 主流语言；
- 代码、数学或领域文本；
- 不同输入长度；
- system prompt；
- 业务中常见的特殊 token。

校准数据过窄会产生两个问题：
1. scale 不能覆盖线上输入；
2. 选出的 alpha 只适合局部分布。

需要固定随机种子并记录：
- 样本来源；
- 样本数；
- 截断长度；
- tokenizer；
- 模型 revision；
- alpha；
- 量化粒度与排除层。
## 工程流程
下面是工具无关流程，不是某个量化库的可执行 API：
```python
# 伪代码：字段名由实际量化工具决定
model = load_fp_model(model_id, revision=revision)
stats = collect_activation_max(
    model,
    calibration_samples,
)
scales = choose_smooth_scales(
    activation_stats=stats,
    weights=model.weights,
    alpha=0.5,
)
fold_scales_into_model(model, scales)
quantize_weights_and_activations(
    model,
    weight_dtype="int8",
    activation_dtype="int8",
)
export_checkpoint(model, output_dir)
```
真正执行时，应使用量化工具的官方示例与版本文档。导出后还要确认：
- checkpoint 中保存了什么 scale；
- vLLM 能否识别量化配置；
- 目标 GPU 是否支持相应实现；
- 日志中是否选择预期 Kernel。
## 硬件与 Kernel 约束
### GPU 代际
不同 GPU 对 INT8 Tensor Core 的支持不同。即使硬件支持 INT8，推理框架也要有适配该架构的 Kernel。
不要根据“CUDA 可用”推断“W8A8 高效”。
### 维度对齐
Tensor Core Kernel 通常要求矩阵维度满足一定倍数。Tensor Parallel 切分可能改变局部维度。
模型原维度对齐，不代表每个 rank 上仍对齐。
### 算子覆盖
如果只有部分 Linear 使用 INT8，其他算子仍可能成为瓶颈。应通过 profiler 或引擎日志确认：
- INT8 GEMM 占比；
- 量化/反量化 Kernel 开销；
- dtype cast；
- 回退 Kernel；
- 通信时间。
### Shape 与并发
Prefill 常有较大的矩阵，更容易利用矩阵乘吞吐。Decode 在小 batch 下矩阵更“瘦”，可能更受权重带宽和 Kernel 启动开销影响。
因此 W8A8 对 Prefill 和 Decode 的收益可能不同。
## Trade-off
### 相比 FP16/BF16
潜在优势：
- 权重显存更小；
- 激活带宽更低；
- 可利用 INT8 Tensor Core；
- 大矩阵计算可能更高效。

潜在代价：
- 需要校准；
- 激活量化有额外开销；
- 离群值和分布漂移带来质量风险；
- 兼容性不如高精度路径普遍。
### 相比 Weight-only INT4
W8A8：
- 位宽更高，通常更容易保持质量；
- 同时量化激活，有原生整数计算潜力；
- 权重压缩不如 INT4。

INT4 Weight-only：
- 权重更省显存和带宽；
- 激活常保留 FP16/BF16；
- 依赖融合反量化 Kernel；
- 对 Decode 的权重带宽瓶颈可能更有吸引力。

没有统一赢家。要看硬件、模型、阶段和 SLO。
## 如何验证 SmoothQuant
至少准备三组：
1. 原始 FP16/BF16 基线；
2. 直接 W8A8（若工具支持）；
3. SmoothQuant W8A8。

质量对比应包括：
- 校准分布内任务；
- 分布外但合法的输入；
- 长上下文；
- 数学、代码和结构化输出；
- 业务关键样本。

性能对比应保持：
- 相同 GPU；
- 相同 vLLM 版本；
- 相同并行策略；
- 相同请求集合；
- 相同采样参数；
- 相同预热；
- 相同并发扫描。

不要用单条 Prompt 的墙钟时间下结论。
## 常见失败模式
### alpha 过大
激活变平滑，但权重某些通道被放大，导致权重量化误差上升。
### 校准集失配
离线统计没有覆盖线上激活，固定 scale 发生严重 clip。
### 分支折叠错误
缩放只应用到部分共享分支，破坏数学等价性。
### 格式能导出但引擎不支持
量化工具与服务引擎对配置字段、打包布局或 scale 粒度理解不一致。
### Kernel 回退
模型可以生成，但实际没有走 INT8 高性能路径。这时质量可能正常，性能却不符合预期。
## 本节小结
W8A8 同时量化权重与激活。它的核心难点是输入相关的激活，尤其是少数通道中的离群值。SmoothQuant 插入按通道的等价缩放：
- 激活除以 \(s\)；
- 权重乘以 \(s\)；
- 原始浮点函数不变；
- 量化误差在两侧重新分配。

alpha 控制迁移强度，校准数据决定统计是否可信，而真实收益最终由 INT8 Kernel 覆盖和 workload 决定。
