## 先说人话：量化是在换尺子
假设要记录一组人的身高。用浮点数可以写成：
```text
171.23, 168.91, 182.47, ...
```
如果业务只关心厘米，可以写成整数：
```text
171, 169, 182, ...
```
数字占用更少，代价是丢掉小数部分。神经网络量化也是同一件事：
- 原来的浮点数是细刻度尺；
- INT8、INT4 是格子更少的尺子；
- `scale` 决定一格代表多大；
- `zero-point` 决定整数零对应哪个实数；
- 舍入与截断造成量化误差。

量化不是简单把 `float` 强转为 `int`。真正的问题是：
> 怎样用有限的格子覆盖原数据范围，同时尽量保留有用差异？
## 从公式看“换尺子”
最常见的仿射量化写作：
\[q = \operatorname{clip}\left( \operatorname{round}\left(\frac{x}{s}\right)+z,\, q_{\min}, q_{\max} \right)\]
反量化写作：
\[\hat{x}=s(q-z)\]
其中：
- \(x\)：原始浮点数；
- \(q\)：存储的整数；
- \(s\)：scale，且 \(s>0\)；
- \(z\)：zero-point；
- \([q_{\min},q_{\max}]\)：整数可表示范围；
- \(\hat{x}\)：反量化后的近似值。

误差是：
\[e=x-\hat{x}\]
如果数值没有被 clip，四舍五入的绝对误差通常不超过半个刻度：
\[|e|\le \frac{s}{2}\]
因此 scale 越小，刻度越细。但 scale 太小又覆盖不了大值，超出范围的数据会被截断。这就是量化最基本的取舍：
> 舍入误差和截断误差不能同时无限小。
## 手算一次对称 INT8
考虑张量：
```text
x = [-1.2, -0.3, 0.0, 0.8, 1.0]
```
有符号 INT8 通常使用：
```text
q_min = -127
q_max = 127
```
这里故意不使用 `-128`，让正负范围保持对称。最大绝对值为：
\[\max |x|=1.2\]
scale 为：
\[s=\frac{1.2}{127}\approx 0.009449\]
量化 `0.8`：
\[q=\operatorname{round}(0.8/0.009449)\approx 85\]
反量化：
\[\hat{x}=85\times 0.009449\approx 0.803\]
误差约为：
\[e=0.8-0.803=-0.003\]
这个结果没有“精确恢复”原数值，但误差落在半个 scale 附近。
## 对称量化与非对称量化
### 对称量化
对称量化令：
\[z=0\]
scale 常按最大绝对值计算：
\[s=\frac{\max |x|}{q_{\max}}\]
优点：
- 公式简单；
- zero-point 处理更少；
- 更容易映射到高效矩阵乘 Kernel；
- 权重量化中很常见。

缺点：
- 如果数据范围明显偏向一侧，会浪费格子。

例如数据都在 `[0, 1]`，有符号 INT8 的负半边就没有被利用。
### 非对称量化
非对称量化让实数最小值和最大值尽量映射到整数两端：
\[s=\frac{x_{\max}-x_{\min}}{q_{\max}-q_{\min}}\]
\[z=\operatorname{round}\left(q_{\min}-\frac{x_{\min}}{s}\right)\]
再把 \(z\) clip 到整数范围。优点：
- 对偏置分布能利用更多整数格子；
- 激活为非负时可能更合适。

缺点：
- 矩阵乘中需要处理 zero-point 修正；
- 实现和融合更复杂；
- 未必有目标 Kernel 支持。

算法上更精确，不代表系统上更快。
## 位宽决定格子数量
一个 \(b\) 位无符号整数有：
\[2^b\]
个编码。常见情况：
- INT8：256 个编码；
- INT4：16 个编码；
- INT2：4 个编码。

位宽每减少一半，存储通常也接近减少一半。但可用刻度会指数减少。因此从 8 bit 降到 4 bit，不是“少一点精度”，而是从数百个格子降到十几个格子。
## 量化粒度：几个人共用一把尺子
### Per-tensor
整个张量共用一个 scale。优点：
- 元数据少；
- 实现简单；
- Kernel 容易高效。

缺点：
- 一个离群值就能拉大所有元素的刻度。
### Per-channel
每个输出通道或输入通道使用独立 scale。对于线性层权重 \(W\)，到底沿哪个轴量化取决于框架和 Kernel 约定。优点：
- 能适应通道间范围差异；
- 权重 INT8 中通常精度更好。

缺点：
- scale 更多；
- 轴语义不一致会导致加载错误或错误结果。
### Per-group
每连续 \(G\) 个权重共用一个 scale。例如 `group_size=128` 表示每组 128 个值。
它位于 per-tensor 与 per-element 之间。group 越小：
- scale 趓多；
- 对局部分布适应更好；
- 元数据与索引开销更高；
- Kernel 的向量化和访存可能更困难。

group 越大则相反。不要只按精度选择 group size，还要确认目标 Kernel 支持哪些尺寸。
### Per-token 与 Per-block
激活动态量化常按 token 计算 scale。低比特浮点或 KV Cache 也常按固定 block 共享 scale。
这些粒度能跟随输入变化，但会增加运行时统计和 scale 读写。
## 静态量化与动态量化
### 静态量化
部署前用校准数据确定 scale。推理时直接使用固定参数。好处是运行时开销小，风险是线上分布可能超出校准范围。
### 动态量化
推理时根据当前张量计算 scale。好处是能适应输入变化，代价是要执行：
- 最大值或统计量归约；
- scale 计算；
- 量化；
- 可能的同步。

当矩阵很小或 Decode batch 很小时，这些额外操作可能不能忽略。
## 校准：先量一遍再定尺子
校准数据不是训练数据的随便一小撮。它应覆盖真实请求中的：
- 语言与领域；
- 输入长度；
- Prompt 模板；
- 特殊 token；
- 多模态输入形态（若适用）；
- 极端但合法的请求。

常见范围估计方法包括：
- min-max；
- percentile clipping；
- 均方误差最小化；
- KL divergence；
- 针对特定算法的激活统计。

“覆盖最大值”不一定误差最小。如果最大值只是极少数离群点，适当截断可能让主体分布得到更细刻度。但截断阈值必须通过任务质量验证。
## PTQ 与 QAT
### PTQ：训练后量化
Post-Training Quantization 在模型训练完成后进行。典型流程：
1. 加载浮点模型；
2. 收集少量校准样本；
3. 计算 scale 或重要性；
4. 生成量化权重与配置；
5. 在目标引擎验证。

优点：
- 不需要重新训练完整模型；
- 成本较低；
- 适合快速部署。

缺点：
- 极低位宽下更容易损失质量；
- 对校准数据和算法较敏感。

SmoothQuant、GPTQ、AWQ 通常归入 PTQ 路线。
### QAT：量化感知训练
Quantization-Aware Training 在训练中模拟量化误差。常见做法是使用 fake quant：
```text
浮点权重 -> 模拟量化/反量化 -> 浮点计算 -> 反向传播
```
前向传播看到低精度噪声，梯度仍以可训练方式近似传递。优点：
- 模型能主动适应量化误差；
- 低位宽下往往更有质量潜力。

缺点：
- 需要训练数据与训练预算；
- 训练流程复杂；
- 产物仍要匹配推理 Kernel 的格式。

QAT 解决“模型能否适应”，不能自动解决“引擎能否高效执行”。
## 伪量化不等于真实加速
下面是教学用伪代码：
```python
# 伪代码：只展示数学，不是高性能量化 Kernel
scale = max(abs(x)) / 127
q = round(x / scale).clip(-127, 127).to(int8)
x_hat = q.to(float16) * scale
```
如果每次计算前都把整个张量恢复为 FP16，它可能节省磁盘或显存，但不一定减少计算时间。高性能实现通常要：
- 以打包格式读取低比特权重；
- 在寄存器或共享内存中处理 scale；
- 将反量化与矩阵乘融合；
- 或直接使用原生低精度 Tensor Core 指令。

所以验证时要区分：
- 模型格式；
- 内存中的实际 dtype；
- 计算 Kernel；
- 累加 dtype；
- 输出 dtype。
## 硬件与 Kernel 约束
量化效果受硬件路径约束。需要检查：
1. GPU Compute Capability；
2. 目标数据类型是否有原生 Tensor Core；
3. 矩阵维度是否满足对齐要求；
4. group size 是否被 Kernel 支持；
5. batch、sequence length 是否适合该 Kernel；
6. Tensor Parallel 切分后维度是否仍对齐；
7. 推理引擎是否会回退到较慢实现。

一个常见陷阱是：
> checkpoint 标注为 INT4，但运行时主要计算仍是 FP16。
这不一定是 bug。
Weight-only 路径本来就可能把 INT4 权重反量化后，与 FP16/BF16 激活完成矩阵乘。
关键在于反量化是否融合、访存是否减少，以及目标 workload 是否带宽受限。
## 误差如何传播
对线性层：
\[y=Wx\]
量化后：
\[\hat{y}=(W+\Delta W)(x+\Delta x)\]
展开：
\[\hat{y}=Wx+W\Delta x+\Delta W x+\Delta W\Delta x\]
输出误差不只由权重误差大小决定，还与输入激活和层敏感度有关。这解释了为什么：
- 相同量化误差对不同层影响不同；
- 少量重要通道值得更精细保护；
- 只看权重重建 MSE 不足以代表生成质量。
## 工程验证清单
量化产物生成后，至少检查以下内容。
### 正确性
- 模型能否加载；
- tokenizer 与原模型是否一致；
- 短输入、长输入是否都能生成；
- 是否出现 NaN、重复或空输出；
- 多 GPU 切分是否正常。
### 质量
- 固定评测集上的任务指标；
- 长文本、代码、数学等关键场景；
- 与浮点基线逐样本对比；
- 业务安全与格式约束；
- 必要时再看 perplexity。
### 系统
- 模型权重显存；
- 峰值显存；
- TTFT；
- TPOT；
- 请求吞吐；
- P50/P95/P99 延迟；
- 不同并发和上下文长度。
### 可复现性
- GPU 型号与驱动；
- CUDA 与框架版本；
- vLLM 版本；
- checkpoint 版本或 commit；
- 完整启动参数；
- 输入分布与预热策略。
## 常见误区
### 误区一：位宽就是全部
同为 INT4，量化粒度、算法、打包布局和 Kernel 可能完全不同。
### 误区二：压缩比等于加速比
速度还受计算、调度、通信和反量化开销影响。
### 误区三：校准集越大越好
覆盖分布比盲目增加数量更重要。
### 误区四：平均质量不降就安全
平均值可能掩盖少数关键任务的大幅回退。
### 误区五：能启动就表示配置正确
有的引擎会回退，有的错误只在特定长度或并行配置下出现。
## 本节小结
量化的核心是用有限编码近似连续数值。scale 决定刻度，zero-point 决定原点，粒度决定多少数据共用一把尺子。
更细粒度通常有利于精度，但增加元数据和 Kernel 复杂度。
PTQ 成本低，QAT 让模型主动适应误差，两者最终都必须落到真实硬件和真实 Kernel。
判断量化方案时，不要停在“模型是几 bit”，而要追问存储、计算、累加、硬件和服务 SLO。
