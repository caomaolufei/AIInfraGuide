## 先说人话：量化是在换尺子
假设要记录一组人的身高。用浮点数可以写成：
```text
171.23, 168.91, 182.47, ...
```
如果业务只关心厘米，可以写成整数：
```text
171, 169, 182, ...
```
数字占用更少，代价是丢掉小数部分。神经网络量化也是同一件事：
- 原来的浮点数是细刻度尺；
- INT8、INT4 是格子更少的尺子；
- `scale` 决定一格代表多大；
- `zero-point` 决定整数零对应哪个实数；
- 舍入与截断造成量化误差。

量化不是简单把 `float` 强转为 `int`。真正的问题是：
> 怎样用有限的格子覆盖原数据范围，同时尽量保留有用差异？
## 从公式看“换尺子”
最常见的仿射量化写作：
\[q = \operatorname{clip}\left( \operatorname{round}\left(\frac{x}{s}\right)+z,\, q_{\min}, q_{\max} \right)\]
反量化写作：
\[\hat{x}=s(q-z)\]
其中：
- \(x\)：原始浮点数；
- \(q\)：存储的整数；
- \(s\)：scale，且 \(s>0\)；
- \(z\)：zero-point；
- \([q_{\min},q_{\max}]\)：整数可表示范围；
- \(\hat{x}\)：反量化后的近似值。

误差是：
\[e=x-\hat{x}\]
如果数值没有被 clip，四舍五入的绝对误差通常不超过半个刻度：
\[|e|\le \frac{s}{2}\]
因此 scale 越小，刻度越细。但 scale 太小又覆盖不了大值，超出范围的数据会被截断。这就是量化最基本的取舍：
> 舍入误差和截断误差不能同时无限小。
## 手算一次对称 INT8
考虑张量：
```text
x = [-1.2, -0.3, 0.0, 0.8, 1.0]
```
有符号 INT8 通常使用：
```text
q_min = -127
q_max = 127
```
这里故意不使用 `-128`，让正负范围保持对称。最大绝对值为：
\[\max |x|=1.2\]
scale 为：
\[s=\frac{1.2}{127}\approx 0.009449\]
量化 `0.8`：
\[q=\operatorname{round}(0.8/0.009449)\approx 85\]
反量化：
\[\hat{x}=85\times 0.009449\approx 0.803\]
误差约为：
\[e=0.8-0.803=-0.003\]
这个结果没有“精确恢复”原数值，但误差落在半个 scale 附近。
## 对称量化与非对称量化
### 对称量化
对称量化令：
\[z=0\]
scale 常按最大绝对值计算：
\[s=\frac{\max |x|}{q_{\max}}\]
优点：
- 公式简单；
- zero-point 处理更少；
- 更容易映射到高效矩阵乘 Kernel；
- 权重量化中很常见。

缺点：
- 如果数据范围明显偏向一侧，会浪费格子。

例如数据都在 `[0, 1]`，有符号 INT8 的负半边就没有被利用。
### 非对称量化
非对称量化让实数最小值和最大值尽量映射到整数两端：
\[s=\frac{x_{\max}-x_{\min}}{q_{\max}-q_{\min}}\]
\[z=\operatorname{round}\left(q_{\min}-\frac{x_{\min}}{s}\right)\]
再把 \(z\) clip 到整数范围。优点：
- 对偏置分布能利用更多整数格子；
- 激活为非负时可能更合适。

缺点：
- 矩阵乘中需要处理 zero-point 修正；
- 实现和融合更复杂；
- 未必有目标 Kernel 支持。

算法上更精确，不代表系统上更快。
## 位宽决定格子数量
一个 \(b\) 位无符号整数有：
\[2^b\]
个编码。常见情况：
- INT8：256 个编码；
- INT4：16 个编码；
- INT2：4 个编码。

位宽每减少一半，存储通常也接近减少一半。但可用刻度会指数减少。因此从 8 bit 降到 4 bit，不是“少一点精度”，而是从数百个格子降到十几个格子。
## 量化粒度：几个人共用一把尺子
### Per-tensor
整个张量共用一个 scale。优点：
- 元数据少；
- 实现简单；
- Kernel 容易高效。

缺点：
- 一个离群值就能拉大所有元素的刻度。
### Per-channel
每个输出通道或输入通道使用独立 scale。对于线性层权重 \(W\)，到底沿哪个轴量化取决于框架和 Kernel 约定。优点：
- 能适应通道间范围差异；
- 权重 INT8 中通常精度更好。

缺点：
- scale 更多；
- 轴语义不一致会导致加载错误或错误结果。
### Per-group
每连续 \(G\) 个权重共用一个 scale。例如 `group_size=128` 表示每组 128 个值。
它位于 per-tensor 与 per-element 之间。group 越小：
- scale 趓多；
- 对局部分布适应更好；
- 元数据与索引开销更高；
- Kernel 的向量化和访存可能更困难。

group 越大则相反。不要只按精度选择 group size，还要确认目标 Kernel 支持哪些尺寸。
### Per-token 与 Per-block
激活动态量化常按 token 计算 scale。低比特浮点或 KV Cache 也常按固定 block 共享 scale。
这些粒度能跟随输入变化，但会增加运行时统计和 scale 读写。
## 静态量化与动态量化
### 静态量化
部署前用校准数据确定 scale。推理时直接使用固定参数。好处是运行时开销小，风险是线上分布可能超出校准范围。
### 动态量化
推理时根据当前张量计算 scale。好处是能适应输入变化，代价是要执行：
- 最大值或统计量归约；
- scale 计算；
- 量化；
- 可能的同步。

当矩阵很小或 Decode batch 很小时，这些额外操作可能不能忽略。
## 校准：先量一遍再定尺子
校准数据不是训练数据的随便一小撮。它应覆盖真实请求中的：
- 语言与领域；
- 输入长度；
- Prompt 模板；
- 特殊 token；
- 多模态输入形态（若适用）；
- 极端但合法的请求。

常见范围估计方法包括：
- min-max；
- percentile clipping；
- 均方误差最小化；
- KL divergence；
- 针对特定算法的激活统计。

“覆盖最大值”不一定误差最小。如果最大值只是极少数离群点，适当截断可能让主体分布得到更细刻度。但截断阈值必须通过任务质量验证。
## PTQ 与 QAT
### PTQ：训练后量化
Post-Training Quantization 在模型训练完成后进行。典型流程：
1. 加载浮点模型；
2. 收集少量校准样本；
3. 计算 scale 或重要性；
4. 生成量化权重与配置；
5. 在目标引擎验证。

优点：
- 不需要重新训练完整模型；
- 成本较低；
- 适合快速部署。

缺点：
- 极低位宽下更容易损失质量；
- 对校准数据和算法较敏感。

SmoothQuant、GPTQ、AWQ 通常归入 PTQ 路线。
### QAT：量化感知训练
Quantization-Aware Training 在训练中模拟量化误差。常见做法是使用 fake quant：
```text
浮点权重 -> 模拟量化/反量化 -> 浮点计算 -> 反向传播
```
前向传播看到低精度噪声，梯度仍以可训练方式近似传递。优点：
- 模型能主动适应量化误差；
- 低位宽下往往更有质量潜力。

缺点：
- 需要训练数据与训练预算；
- 训练流程复杂；
- 产物仍要匹配推理 Kernel 的格式。

QAT 解决“模型能否适应”，不能自动解决“引擎能否高效执行”。
## 伪量化不等于真实加速
下面是教学用伪代码：
```python
# 伪代码：只展示数学，不是高性能量化 Kernel
scale = max(abs(x)) / 127
q = round(x / scale).clip(-127, 127).to(int8)
x_hat = q.to(float16) * scale
```
如果每次计算前都把整个张量恢复为 FP16，它可能节省磁盘或显存，但不一定减少计算时间。高性能实现通常要：
- 以打包格式读取低比特权重；
- 在寄存器或共享内存中处理 scale；
- 将反量化与矩阵乘融合；
- 或直接使用原生低精度 Tensor Core 指令。

所以验证时要区分：
- 模型格式；
- 内存中的实际 dtype；
- 计算 Kernel；
- 累加 dtype；
- 输出 dtype。
## 硬件与 Kernel 约束
量化效果受硬件路径约束。需要检查：
1. GPU Compute Capability；
2. 目标数据类型是否有原生 Tensor Core；
3. 矩阵维度是否满足对齐要求；
4. group size 是否被 Kernel 支持；
5. batch、sequence length 是否适合该 Kernel；
6. Tensor Parallel 切分后维度是否仍对齐；
7. 推理引擎是否会回退到较慢实现。

一个常见陷阱是：
> checkpoint 标注为 INT4，但运行时主要计算仍是 FP16。
这不一定是 bug。
Weight-only 路径本来就可能把 INT4 权重反量化后，与 FP16/BF16 激活完成矩阵乘。
关键在于反量化是否融合、访存是否减少，以及目标 workload 是否带宽受限。
## 误差如何传播
对线性层：
\[y=Wx\]
量化后：
\[\hat{y}=(W+\Delta W)(x+\Delta x)\]
展开：
\[\hat{y}=Wx+W\Delta x+\Delta W x+\Delta W\Delta x\]
输出误差不只由权重误差大小决定，还与输入激活和层敏感度有关。这解释了为什么：
- 相同量化误差对不同层影响不同；
- 少量重要通道值得更精细保护；
- 只看权重重建 MSE 不足以代表生成质量。

## 问题驱动：一份量化配置究竟在承诺什么
看到 `int8`、`group_size=128` 或 `dynamic` 时，先不要问“压缩了多少”，而要把配置还原成五个可验证问题：

1. **编码域是什么？** `int8` 的 `[-128, 127]`、对称 `[-127, 127]`，还是存放在 `uint8` 中的仿射编码？
2. **谁共享 scale？** 整张量、某个轴、每 128 个元素、每个 token，还是一个 Kernel tile？
3. **范围怎样得到？** 固定 min-max、百分位截断、校准搜索，还是每次前向动态归约？
4. **布局怎样解释？** scale 的第 \(i\) 项对应逻辑矩阵哪一行、哪一列或哪一组？
5. **谁消费这些字节？** 教学反量化、融合 GEMM，还是原生低精度指令？

如果这五项有一项不清楚，“INT8 模型”仍不是一个完整的工程规格。

## 从区间映射推导 affine quantization
不要背 scale 公式。先要求实数区间 \([x_{\min},x_{\max}]\) 线性映射到整数区间
\([q_{\min},q_{\max}]\)：

\[
x \approx s(q-z)
\]

两个端点满足：

\[
x_{\min}=s(q_{\min}-z),\qquad
x_{\max}=s(q_{\max}-z)
\]

两式相减：

\[
x_{\max}-x_{\min}=s(q_{\max}-q_{\min})
\]

所以：

\[
s=\frac{x_{\max}-x_{\min}}{q_{\max}-q_{\min}}
\]

再由第一个端点得到实数意义上的 zero-point：

\[
z^*=q_{\min}-\frac{x_{\min}}{s}
\]

但编码要求 \(z\) 是范围内的整数，因此真正保存的是：

\[
z=\operatorname{clip}(\operatorname{round}(z^*),q_{\min},q_{\max})
\]

这一步会使两个实数端点不一定同时精确可表示。仿射量化优先保证的是：

- 整数编码合法；
- 实数零尽量可精确表示；
- 尽量覆盖所选区间；zero-point 舍入后端点可能轻微饱和；
- 其余值落到最近网格点。

完整顺序不能随意交换：

\[
r=x/s,\quad
n=\operatorname{round}(r),\quad
q=\operatorname{clip}(n+z,q_{\min},q_{\max})
\]

先 `clamp(x)` 再除 scale 在理想实数中可得到相近结果，但在有限精度实现、非整数
zero-point 中间值或特殊舍入规则下不能假设逐 bit 相同。模型格式应明确规定运算顺序。

## 非对称 UINT8：逐项手算
令：

```text
x = [-1.0, -0.2, 0.3, 1.4]
q_min = 0, q_max = 255
```

则：

\[
s=\frac{1.4-(-1.0)}{255}=\frac{2.4}{255}\approx0.00941176
\]

\[
z^*=0-\frac{-1.0}{0.00941176}=106.25,\qquad z=106
\]

逐项计算：

```text
x       x/s          round(x/s)   +z    q
-1.0   -106.250      -106           0     0
-0.2    -21.250       -21          85    85
 0.3     31.875        32         138   138
 1.4    148.750       149         255   255
```

反量化：

```text
q       s * (q-z)      error = x_hat-x
0       -0.997647       0.002353
85      -0.197647       0.002353
138      0.301176       0.001176
255      1.402353       0.002353
```

端点出现小误差不是公式错了，而是 \(z^*=106.25\) 必须舍入成整数。若某实现使用
`round half away from zero`，另一个使用 ties-to-even，它们在半格位置会产生不同编码。
PyTorch 的 `torch.round` 对恰好一半采用 round-to-even；生产 Kernel 是否相同必须查其规格。

## clamp、round 与三类误差
将误差拆开比笼统说“精度损失”更有用。

### 网格舍入误差
未饱和且使用最近邻舍入时：

\[
e_r=x-\hat{x},\qquad |e_r|\le s/2
\]

若网格足够细且信号相对网格相位近似均匀，常用的噪声模型给出：

\[
\mathbb{E}[e_r]\approx0,\qquad
\operatorname{Var}(e_r)\approx\frac{s^2}{12}
\]

这是建模近似，不是任意神经网络张量上的定理。权重集中在零附近、舍入相关性和大量相同值都可能破坏“均匀噪声”假设。

### 饱和误差
当 \(x>x_{\max}^{\text{representable}}\)：

\[
\hat{x}=s(q_{\max}-z),\qquad
e_c=x-\hat{x}
\]

它没有 \(s/2\) 上界，少量极端值就可能主导 MSE。percentile clipping 的目标正是允许少量
\(e_c\)，换取主体更小的 \(e_r\)。

### 参数估计误差
校准样本给出的 \(\hat{x}_{\min},\hat{x}_{\max}\) 与线上分布不同，会产生错误 scale。它不是单次舍入噪声，而是系统性分布失配。动态量化能减轻范围估计误差，但会引入运行时归约成本。

此外还有：

- scale 本身以 FP16/FP8 保存导致的 scale 量化误差；
- FP16 中执行 `x / s` 的中间舍入；
- 累加精度与归约顺序变化；
- 融合 epilogue 中 bias、activation 的重排误差。

## 粒度必须同时写出逻辑轴和物理轴
设线性层采用 PyTorch 逻辑权重：

```text
W.shape = [out_features, in_features]
y = x @ W.T
```

若做 per-output-channel 对称量化：

\[
s_o=\frac{\max_i|W_{o,i}|}{127},\qquad
Q_{o,i}=\operatorname{round}(W_{o,i}/s_o)
\]

逻辑上 `scale.shape == [out_features]`，广播形式是 `scale[:, None]`。但 GEMM Kernel 可能要求
预转置或 tile-reordered 权重。磁盘中的第一个维度不一定仍是逻辑 `out_features`。

对于 group-wise：

```text
W:      [O, I]
G:      group_size
groups: ceil(I / G)
scale:  [O, groups]
```

逻辑元素 \((o,i)\) 使用：

\[
g=\lfloor i/G\rfloor,\qquad s=s_{o,g}
\]

若 \(I\) 不能被 \(G\) 整除，格式必须约定最后一组是 padding、短组，还是直接不支持。
Tensor Parallel 把 \(I\) 或 \(O\) 切分后，也必须重新检查 group 边界和 scale shard。

### INT4 nibble 的最小布局例子
两个无符号 4-bit 编码 \(q_0,q_1\in[0,15]\) 可打包为：

\[
b=(q_1\ll4)\ |\ q_0
\]

解包：

\[
q_0=b\ \&\ 0x0F,\qquad q_1=(b\gg4)\ \&\ 0x0F
\]

如果有符号值使用 offset 编码，例如逻辑 \([-8,7]\) 存为 `q + 8`，解包后还要减 8。
也有实现直接做 4-bit 二补码符号扩展。两者的字节可能相同或不同，不能凭“INT4”猜。

## 可复现实验：用 PyTorch 验证公式
下面程序只验证数学与布局，不宣称触发低精度加速。CPU 即可运行，建议记录 PyTorch 版本。

```python
import torch

torch.manual_seed(0)
torch.set_printoptions(precision=6, sci_mode=False)

def affine_qdq(x, qmin, qmax, xmin=None, xmax=None):
    xmin = x.min() if xmin is None else torch.as_tensor(xmin, dtype=x.dtype)
    xmax = x.max() if xmax is None else torch.as_tensor(xmax, dtype=x.dtype)
    if not bool(xmax > xmin):
        # 常量张量需要格式约定；这里只做避免除零的教学退化，不保证精确恢复任意常量。
        scale = torch.ones((), dtype=x.dtype)
        zp = torch.clamp(torch.round(qmin - xmin / scale), qmin, qmax)
    else:
        scale = (xmax - xmin) / float(qmax - qmin)
        zp = torch.clamp(torch.round(qmin - xmin / scale), qmin, qmax)
    q = torch.clamp(torch.round(x / scale) + zp, qmin, qmax).to(torch.int32)
    x_hat = scale * (q.to(x.dtype) - zp)
    return q, x_hat, scale, zp.to(torch.int32)

x = torch.tensor([-1.0, -0.2, 0.3, 1.4], dtype=torch.float64)
q, x_hat, scale, zp = affine_qdq(x, 0, 255)
print("scale, zero_point:", scale.item(), zp.item())
print("q:", q)
print("x_hat:", x_hat)
print("max_abs_error:", (x_hat - x).abs().max().item())

# 人工收紧范围，观察舍入误差下降但饱和误差出现。
for bound in (1.4, 1.0, 0.5):
    q, x_hat, s, _ = affine_qdq(x, 0, 255, xmin=-1.0, xmax=bound)
    print(bound, "scale=", s.item(), "mse=", ((x_hat - x) ** 2).mean().item())
```

### 验证 per-channel 广播

```python
import torch

W = torch.tensor([
    [-1.0, -0.5, 0.0, 1.0],
    [-8.0, -0.5, 0.0, 4.0],
], dtype=torch.float32)
s = W.abs().amax(dim=1, keepdim=True) / 127
Q = torch.clamp(torch.round(W / s), -127, 127).to(torch.int8)
W_hat = Q.float() * s

print("scale shape:", tuple(s.shape))       # (2, 1)
print("codes:\n", Q)
print("row mse:", ((W_hat - W) ** 2).mean(dim=1))
assert Q.shape == W.shape
assert torch.all(Q.abs().to(torch.int16) <= 127)
```

第二行的 `-8` 不会拉粗第一行的刻度，这就是 per-channel 相对 per-tensor 的直接收益。

### 静态与动态量化的对照

```python
import torch

def sym_qdq(x, amax):
    s = torch.as_tensor(amax, dtype=x.dtype).clamp_min(torch.finfo(x.dtype).tiny) / 127
    q = torch.clamp(torch.round(x / s), -127, 127)
    return q * s

calib = torch.randn(4096)
static_amax = calib.abs().quantile(0.999)
online = torch.cat([torch.randn(4095), torch.tensor([20.0])])

static_hat = sym_qdq(online, static_amax)
dynamic_hat = sym_qdq(online, online.abs().max())
body = online.abs() < 3

print("static clipped:", int((online.abs() > static_amax).sum()))
print("static body mse:", ((static_hat[body] - online[body]) ** 2).mean().item())
print("dynamic body mse:", ((dynamic_hat[body] - online[body]) ** 2).mean().item())
```

预期现象是：静态 99.9% 阈值会截断线上离群值；动态 max 保住离群值，却可能因 scale 被 20 拉大而增加主体误差。不要把这段随机实验的具体输出当成模型结论。

## 校准阈值：从“覆盖范围”变成可优化目标
给定候选阈值 \(t\)，对称量化的仿真重建是：

\[
\hat{x}(t)=\frac{t}{q_{\max}}
\operatorname{clip}\left(
\operatorname{round}\left(\frac{xq_{\max}}{t}\right),
-q_{\max},q_{\max}
\right)
\]

MSE 搜索可写为：

\[
t^*=\arg\min_t\sum_i(x_i-\hat{x}_i(t))^2
\]

也可以优化 KL divergence 或直接最小化层输出误差
\(\|XW-X\hat{W}\|_2^2\)。三者目标不同：

- tensor MSE 偏向数值重建；
- KL 更关注分布；
- 层输出误差把输入敏感度纳入；
- 端到端任务指标最终决定是否上线。

校准集需要同时留出**未参与选阈值**的验证集，否则阈值搜索也会过拟合。

## Kernel 执行路径：从字节到输出
以动态 INT8 激活乘静态 INT8 权重为例，一条融合路径可能是：

```text
读取 FP16/BF16 activation tile
  -> tile/per-token amax reduction
  -> 计算 activation scale
  -> round + saturate + 写入/驻留 INT8 tile
读取预打包 INT8 weight tile + weight scales
  -> INT8 Tensor Core MMA
  -> INT32 accumulator
  -> 乘 activation_scale * weight_scale
  -> 融合 bias / activation
  -> 写出 FP16/BF16
```

需要区分三种实现：

1. **fake quant**：QDQ 后仍调用普通浮点 GEMM，只测质量；
2. **融合反量化**：压缩数据边读边恢复，再用高精度 MMA，常见于 weight-only；
3. **原生低精度 MMA**：两个低精度输入进入硬件矩阵乘，scale 在 epilogue 应用。

Profiler 中只看到一个短的 quantize Kernel 不能证明 GEMM 已是 INT8；反过来，checkpoint 中没有
FP16 权重副本也不能证明端到端更快。

## 怎样测量质量和性能
### 数值层
对每层或代表性层记录：

\[
\mathrm{MSE}=\frac1n\sum_i(x_i-\hat{x}_i)^2
\]

\[
\mathrm{SQNR}=10\log_{10}
\frac{\sum_i x_i^2}{\sum_i(x_i-\hat{x}_i)^2}
\]

还应记录最大误差、饱和比例、零编码比例、按通道最差值。SQNR 高不保证任务质量好，但能定位异常层。

### 模型层
固定 tokenizer、prompt 模板和 revision，比较：

- teacher-forced perplexity 或 NLL；
- logits cosine/最大绝对误差；
- 任务准确率、代码测试通过率、JSON 合法率；
- 最差业务子集和逐样本回归。

### Kernel 与服务层
微基准必须同时报告矩阵 \(M,N,K\)、dtype、布局、warmup、迭代次数和分位数。服务压测再报告
TTFT、TPOT、吞吐、P95/P99、峰值显存。GPU 异步执行时要用 CUDA Event 或在墙钟计时边界同步：

```python
start = torch.cuda.Event(enable_timing=True)
end = torch.cuda.Event(enable_timing=True)
torch.cuda.synchronize()
start.record()
for _ in range(100):
    y = op(x)
end.record()
torch.cuda.synchronize()
print("mean_ms:", start.elapsed_time(end) / 100)
```

CUDA Event 测的是 GPU 时间，不包含服务排队和网络；两类指标不能互相替代。

## 失败模式与决策边界
- **常量张量**：`xmax == xmin` 会除零；格式必须规定 scale/zp 的退化行为。
- **NaN/Inf 进入统计**：amax 变成 NaN/Inf，后续编码全部失效；校准前应检测而非静默过滤。
- **半格舍入不一致**：导出器和 Kernel 规则不同，边界值不一致。
- **轴错位**：scale 数量看似正确，但转置后应用到错误通道，输出可生成却完全失真。
- **最后一组未对齐**：converter padding 与 Kernel 解释不同。
- **动态量化过细**：数值更准，但归约、scale 写读和同步淹没 GEMM 收益。
- **只测均匀随机数**：未覆盖真实离群通道和 token 分布。

决策时遵循：

- 需要讲清数学或筛选阈值：先用 fake quant；
- 需要部署：先从目标 Kernel 支持的粒度反推格式；
- 激活分布稳定且可校准：静态方案更容易融合；
- 分布变化大：动态方案更稳，但必须单独测量量化开销；
- 质量门槛极高：提高位宽、缩小 group 或保留敏感层，而不是只增加校准样本；
- 找不到实际 Kernel 证据：把收益表述为容量潜力，不声称加速。

## 版本边界
本节代码使用稳定公开的 PyTorch 张量算子，不依赖量化后端；建议在报告中记录
`torch.__version__`。PyTorch 的量化 API 与后端正在演进，教学 QDQ 代码不是
`torch.ao`、TorchAO、TensorRT 或 vLLM 的格式承诺。

截至本文校验日期 **2026-08-13**，本文核对了 vLLM **v0.27.1** tag；其官方量化支持矩阵仍明确提示支持组合会变化。
实际部署必须以已安装版本的 `vllm serve --help`、checkpoint 的量化配置和启动日志三者为准。
硬件“支持 INT8/FP8”也只说明存在某类指令，不保证当前 shape、布局和框架命中该路径。
## 工程验证清单
量化产物生成后，至少检查以下内容。
### 正确性
- 模型能否加载；
- tokenizer 与原模型是否一致；
- 短输入、长输入是否都能生成；
- 是否出现 NaN、重复或空输出；
- 多 GPU 切分是否正常。
### 质量
- 固定评测集上的任务指标；
- 长文本、代码、数学等关键场景；
- 与浮点基线逐样本对比；
- 业务安全与格式约束；
- 必要时再看 perplexity。
### 系统
- 模型权重显存；
- 峰值显存；
- TTFT；
- TPOT；
- 请求吞吐；
- P50/P95/P99 延迟；
- 不同并发和上下文长度。
### 可复现性
- GPU 型号与驱动；
- CUDA 与框架版本；
- vLLM 版本；
- checkpoint 版本或 commit；
- 完整启动参数；
- 输入分布与预热策略。
## 常见误区
### 误区一：位宽就是全部
同为 INT4，量化粒度、算法、打包布局和 Kernel 可能完全不同。
### 误区二：压缩比等于加速比
速度还受计算、调度、通信和反量化开销影响。
### 误区三：校准集越大越好
覆盖分布比盲目增加数量更重要。
### 误区四：平均质量不降就安全
平均值可能掩盖少数关键任务的大幅回退。
### 误区五：能启动就表示配置正确
有的引擎会回退，有的错误只在特定长度或并行配置下出现。
## 本节小结
量化的核心是用有限编码近似连续数值。scale 决定刻度，zero-point 决定原点，粒度决定多少数据共用一把尺子。
更细粒度通常有利于精度，但增加元数据和 Kernel 复杂度。
PTQ 成本低，QAT 让模型主动适应误差，两者最终都必须落到真实硬件和真实 Kernel。
判断量化方案时，不要停在“模型是几 bit”，而要追问存储、计算、累加、硬件和服务 SLO。
