## 本章要解决什么问题

大模型像一间堆满精密仪器的仓库。

FP16、BF16 权重把每个数字保存得比较细，
但仓库容量、搬运带宽和计算单元都要为这份精细付费。

量化做的事，
是给这些数字换一把刻度更粗、占位更小的尺子。

它通常能减少模型与 KV Cache 的显存占用，
有时也能借助低精度 Tensor Core 提高吞吐。

但“文件变小”不等于“服务必然变快”。

真实收益还取决于：

- GPU 是否原生支持目标数据类型；
- 推理引擎是否有匹配的 Kernel；
- 量化与反量化是否落在关键路径；
- 请求处于 Prefill 还是 Decode 阶段；
- 模型质量是否仍满足业务门槛。

本章会把量化拆成四层：

1. 数学层：浮点数怎样映射到低比特数；
2. 算法层：SmoothQuant、GPTQ、AWQ 等怎样减小误差；
3. Kernel 层：低比特数据怎样真正进入 GPU 计算；
4. 服务层：怎样在 vLLM 中验证兼容性、质量与收益。

## 学习路线

### [4.1 量化基础](/AIInfraGuide/inference/模块四-推理优化/第4章-量化/41-量化基础)

先用“刻度尺”理解 scale、zero-point 和舍入误差，
再区分对称/非对称、per-tensor/per-channel/per-group、
静态/动态量化，以及 PTQ/QAT。

完成这一节后，
你应该能手算一个 INT8 量化例子，
也能看懂量化模型配置中的基本字段。

### [4.2 W8A8 与 SmoothQuant](/AIInfraGuide/inference/模块四-推理优化/第4章-量化/42-w8a8-smoothquant)

W8A8 同时压缩权重和激活，
但激活中的离群值会把 INT8 刻度拉得很粗。

SmoothQuant 通过数学等价变换，
把一部分量化难度从激活“搬”到权重，
让静态 INT8 更容易落地。

### [4.3 Weight-only INT4](/AIInfraGuide/inference/模块四-推理优化/第4章-量化/43-weight-only-int4)

Weight-only INT4 只压缩权重，
计算前通常要反量化或由融合 Kernel 边读取边处理。

本节会比较 GPTQ 与 AWQ：

- GPTQ 利用二阶信息补偿逐列量化误差；
- AWQ 利用激活统计保护少量重要权重；
- Marlin 等 Kernel 决定压缩能否变成速度收益。

### [4.4 KV Cache 量化](/AIInfraGuide/inference/模块四-推理优化/第4章-量化/44-kv-cache量化)

长上下文服务中，
增长最快的往往不是模型权重，而是每个请求的 KV Cache。

本节从容量公式出发，
说明 FP8 KV Cache 和 KIVI 类低比特方案的差异，
以及 scale 粒度、校准、Attention Kernel 支持带来的限制。

### [4.5 FP8 与 NVFP4](/AIInfraGuide/inference/模块四-推理优化/第4章-量化/45-fp8与nvfp4)

低比特浮点保留指数，
更适合动态范围大的数据。

本节会区分：

- FP8 的 E4M3 与 E5M2；
- Hopper 上的 FP8 Tensor Core；
- Blackwell 上的 NVFP4；
- OCP MXFP4 与 NVIDIA NVFP4 的概念边界。

硬件支持会随 GPU 代际变化，
因此本节强调能力检查，
而不是给出脱离环境的性能数字。

### [4.6 量化选型与 vLLM 实战](/AIInfraGuide/inference/模块四-推理优化/第4章-量化/46-量化选型与vllm实战)

最后把问题落到工程决策：

- 显存放不下模型时选什么；
- 长上下文容量不足时选什么；
- Hopper、Blackwell 上怎样利用原生低精度；
- vLLM 参数如何以已安装版本的帮助信息为准；
- 怎样同时验证正确性、质量、延迟、吞吐和显存。

## 贯穿本章的判断框架

遇到一种量化格式时，
先按下面顺序提问：

1. **压了什么？** 权重、激活还是 KV Cache？
2. **压到什么？** INT8、INT4、FP8 还是块浮点？
3. **scale 多细？** 每张量、每通道、每组还是每块？
4. **scale 从哪来？** 动态统计、离线校准还是训练学习？
5. **谁来算？** 原生低精度矩阵乘，还是先反量化再计算？
6. **硬件支持吗？** 对应 GPU 是否有目标 Tensor Core 路径？
7. **引擎支持吗？** 模型格式、量化方法与 Kernel 是否匹配？
8. **质量过关吗？** 困惑度只是信号，任务指标才是门槛。
9. **SLO 变好吗？** 关注 TPOT、TTFT、吞吐与尾延迟，而非文件大小。

## 不应预设的结论

以下说法都需要实测，不能直接当成事实：

- “INT4 一定比 FP16 快四倍”；
- “量化后质量肉眼看不出差异”；
- “同一个量化模型能在所有 GPU 上高效运行”；
- “权重缩小一半，服务显存就缩小一半”；
- “能加载就代表用了高性能 Kernel”。

量化经常首先解决“能不能放下”，
其次才是“能不能更快”。
