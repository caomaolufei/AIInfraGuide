前面几节主要用整数刻度描述量化。现在换一个问题：**如果只剩 8 位甚至 4 位，还能不能保留浮点数“用指数照顾大小数”的能力？** Hopper 的 FP8 和 Blackwell 的低比特浮点计算，把这个问题变成了实际的硬件路线。

但看到 FP8 或 FP4，仍不能只盯着数据位宽。真正的数值由编码、Scale、分组和计算 Kernel 一起决定。这一节先讲 FP8 的两种常见表示，再拆开 NVFP4 和 MXFP4 的块缩放，最后把“能存”“能算”和“整模型真的更快”三个层次分清。

## 1. 低比特整数与低比特浮点

均匀整数量化的一组数据共用 Scale，相邻编码对应固定间距。浮点数则用符号位、指数和尾数，让可表示的值随数量级变化：小数附近刻度密，大数附近刻度疏。

对普通规格化二进制浮点值，可以用下面的形式理解：

$$
x=(-1)^\sigma\,2^{e-\text{bias}}(1+m)
$$

其中 $\sigma$ 是符号，$e$ 是指数编码，$m$ 是尾数的小数部分。零、次正规数、NaN 和 Inf 等特殊值需要另外规定，不能只套这一条式子。

用一个类比：均匀整数刻度像普通直尺，整段尺子每格一样长；浮点刻度像地图上的多级缩放，既照顾街道级细节，也能表达城市间距离。但总格子数仍然有限，扩大范围会挤占精度。

📌 **关键点**：FP8 是一种低位宽浮点表示，**不是无损地把 FP16 的字节砍掉一半**。它仍有舍入、下溢和溢出，也仍可能需要外部 Scale。

## 2. E4M3 与 E5M2：范围和精度怎么换

FP8 的两个常见名字直接写出了指数和尾数位数。[FP8 Formats for Deep Learning](https://arxiv.org/abs/2209.05433)讨论了这些表示；具体框架还可能提供带不同特殊值约定的变体。

| 📊 格式 | 位分配 | 常见最大有限绝对值 | 主要取舍 |
|---|---|---|---|
| E4M3（常见 FN 变体） | 1 符号 + 4 指数 + 3 尾数 | 448 | 尾数更多，局部精度较好，范围较小 |
| E5M2 | 1 符号 + 5 指数 + 2 尾数 | 57344 | 范围更大，局部精度较粗 |

表中的数值对应常见的 `float8_e4m3fn` 和 `float8_e5m2`。FNUZ 等变体的偏置和特殊值规则不同，不能只看“E4M3”就默认所有位模式兼容。

### 2.1 为什么多一个指数位会少一点精度

在相同指数区间内，3 位尾数可以区分更多位置；2 位尾数的间距则更大。E5M2 通过更多指数扩大数量级覆盖，代价是同一个数量级里能区分的值更少。

例如围绕 1 的常规规格化区间，E4M3 的刻度间隔为 $2^{-3}=0.125$，E5M2 为 $2^{-2}=0.25$。这只是局部例子，刻度会随指数变化。

### 2.2 推理不能照搬训练习惯

训练中，梯度可能需要很大的动态范围，因此常讨论 E5M2；推理不涉及反向梯度，权重与激活则常见 E4M3 路径。实际采用哪个格式，应看框架、模型导出和硬件支持，不能从“范围更大”推断“精度更好”。

## 3. FP8 也需要 Scale

### 3.1 把数据移到能表示的区间

假设激活最大幅度达到 2000，直接放到最大有限值为 448 的 E4M3，会超出范围。我们仍可先缩放：

$$
q=\operatorname{FP8}(x/s),\qquad \hat{x}=sq
$$

若 $s$ 根据 $\max|x|/448$ 选取，最大的值就能进入范围。实际算法还会考虑安全裕量、误差目标和硬件规则。

Scale 太小会造成大值饱和，Scale 太大可能让小值下溢或丢掉精度。浮点的指数只是增加了适应能力，没有取消校准问题。

### 3.2 Per-tensor、Per-channel 与 Block-wise

- **Per-tensor**：一整个张量共用 Scale，元数据少，局部分布差异大时较粗。
- **Per-channel / Per-token**：给不同权重通道或输入 Token 单独缩放。
- **Block-wise**：局部小块共用 Scale，适应更细的幅度变化，但要求 Kernel 处理块布局与缩放。

权重固定，Scale 可以离线计算；激活会随输入变化，Scale 可以静态校准或运行时动态计算。动态方案需要考虑统计最大值和转换操作能否与已有 Kernel 融合。

🔑 **核心概念**：**FP8 精度不是只由 E4M3/E5M2 决定，还由缩放粒度和 Scale 来源决定。** 两个都叫 FP8 的 checkpoint，数值行为可能明显不同。

## 4. Hopper 的 FP8：存储与计算要分开

H100 所代表的 Hopper 架构提供原生 FP8 Tensor Core 路径，低比特不仅用于保存权重，也能进入矩阵乘法。Ada 及后续架构在框架中也有相应 FP8 计算支持，不能把 FP8 当成 Hopper 独占的概念。[vLLM 的 FP8 文档](https://docs.vllm.ai/en/stable/features/quantization/llm_compressor/fp8/)列出了当前支持范围。

### 4.1 W8A8 与 W8A16 是两条路径

| 📊 路径 | 存储/输入形式 | 主要机会 |
|---|---|---|
| FP8 W8A8 | 权重与激活进入低精度计算 | 减少数据量，利用原生 FP8 GEMM |
| FP8 W8A16 | 权重低比特，激活保留高精度 | 通过兼容 Kernel 降低权重读取量 |
| FP8 KV Cache | 缓存用 FP8 | 降低缓存容量，Attention 计算另行核对 |

例如某些没有原生 FP8 GEMM 的 GPU，可以通过 Weight-only Kernel 运行 FP8 权重模型；这不等于它执行了 Hopper 同样的 FP8 算术。

### 4.2 累加精度也是方案的一部分

低精度输入不意味着所有中间累加都用同样低的位宽。实际 Tensor Core 指令、Kernel 的部分累加和最终输出，会使用指定的累加类型与归约策略。

因此比较质量时，要记录输入 dtype、Scale、累加模式和输出 dtype。把模型文件压到 8 位，只描述了其中一部分。

⚠️ **注意**：原生 FP8 峰值吞吐比 FP16 高，并不保证整模型按同样比例提速。Attention、通信、调度和动态量化开销仍可能是主要瓶颈。

## 5. FP4 的难题：16 个编码怎样够用

常见 FP4 数据编码采用 **E2M1**：1 个符号位、2 个指数位、1 个尾数位。其非负可表示值包括：

$$
0,\ 0.5,\ 1,\ 1.5,\ 2,\ 3,\ 4,\ 6
$$

再加上负值与有符号零，构成 16 个位模式。可用的点太少，单靠一个全张量 Scale 很难同时照顾大量小值和少数大值。

关键转折是：**不让整个张量共用一把尺子，而是让很小的 Block 共用 Scale。** 同一块里的值如果数量级接近，E2M1 的有限刻度就能用得更充分。

这就是低比特浮点里的 **Microscaling（微缩放）** 思想。Scale 成为数值格式的组成部分，硬件和 Kernel 也要能高效读取并应用它。

## 6. NVFP4 与 MXFP4：两种块缩放

[NVIDIA 对 NVFP4 的介绍](https://developer.nvidia.com/blog/introducing-nvfp4-for-efficient-and-accurate-low-precision-inference/)详细比较了它与 MXFP4 的结构。

| 📊 维度 | NVFP4 | MXFP4 |
|---|---|---|
| 数据编码 | E2M1 FP4 | E2M1 FP4 |
| 典型 Block 大小 | 16 个元素 | 32 个元素 |
| 每 Block 的 Scale | E4M3 FP8 | E8M0，仅指数的 2 的幂缩放 |
| 第二级 Scale | 使用额外的 Per-tensor FP32 Scale | 核心块格式不包含 NVFP4 的同款两级设计 |
| 设计取舍 | 更细分组，Scale 可以更灵活 | Scale 规则更简单，元数据比例更低 |

### 6.1 NVFP4：小块加两级缩放

NVFP4 可以用下面的简化重构形式理解：

$$
\hat{x}_{g,i}=s_{\text{tensor}}\,s^{\text{E4M3}}_g\,q^{\text{E2M1}}_{g,i}
$$

每 16 个值用一个 FP8 Scale，整个张量再有一个 FP32 Scale。后者帮助把各块的 Scale 放到合适的可表示范围，前者适应局部分布。

### 6.2 MXFP4：更大的块，幂次 Scale

MXFP4 常用每 32 个值共享一个 E8M0 Scale，可理解为 $2^{e_g}$：

$$
\hat{x}_{g,i}=2^{e_g}q^{\text{E2M1}}_{g,i}
$$

实际格式包含特殊值及编码约定，要以 [OCP Microscaling Formats 规范](https://www.opencompute.org/documents/ocp-microscaling-formats-mx-v1-0-spec-final-pdf)为准。实现还可能额外使用转换或校准参数，不能把简化公式当作所有 checkpoint 的完整布局。

### 6.3 为什么两者不能直接互换

两种格式的数据部分都是 E2M1，但分组长度、Scale 编码、布局与 Kernel 解释不同。同样的 FP4 位模式，配上不同 Scale，就代表不同的实数。

用一个类比：两箱货都贴着“4-bit”，但一箱每 16 件用一张标价卡，另一箱每 32 件用一张，而且标价单位不同。只拷贝货物编码，不转换标签规则，数值就会解释错。

📌 **关键点**：Blackwell 提供原生块缩放低精度计算的机会；**具体型号、指令、框架版本和 Kernel 是否支持某种完整格式，仍要逐项确认**。能通过软件解码 FP4 文件，不等于能使用原生 FP4 GEMM。

## 7. 动手算账：把 Scale 也算进位宽

只写“FP4 每权重 4 位”，会漏掉块 Scale。忽略对齐、未量化层与张量级常数时：

$$
b_{\text{NVFP4}}=4+\frac{8}{16}=4.5\ \text{bits/element}
$$

$$
b_{\text{MXFP4}}=4+\frac{8}{32}=4.25\ \text{bits/element}
$$

理论上相对 FP16 的数据压缩比分别约为 $16/4.5\approx3.56$ 和 $16/4.25\approx3.76$，不是严格四倍。

下面这个小脚本只算存储账本，不测数值质量或实际显存：

```python
import math

def packed_bytes(numel, block_size, tensor_scale_bytes=0):
    data = math.ceil(numel / 2)  # 两个 4-bit 数据值装进一个字节
    block_scales = math.ceil(numel / block_size)  # 每块一个 8-bit Scale
    return data + block_scales + tensor_scale_bytes

numel = 1_000_000
fp16 = numel * 2
for name, block_size, extra in [("NVFP4", 16, 4), ("MXFP4", 32, 0)]:
    size = packed_bytes(numel, block_size, extra)
    print(name, "bytes:", size, "相对 FP16 压缩比:", fp16 / size)
```

真实模型还要按 Tensor 分别计入 Scale、对齐、布局重排与保留高精度的层。MXFP4 的元数据更少，也不能据此断言总是更适合：NVFP4 更细的分组和更灵活的 Scale，可能在某些分布上更容易守住质量。

## 8. 工程实践：从格式到硬件再到评测

### 8.1 先核对三层兼容性

1. **模型层**：是否有正确的低比特权重、Scale、量化配置与对应原模型版本？
2. **框架层**：vLLM 是否支持这种导出格式、架构和所选算子路径？
3. **硬件层**：目标 GPU 是否支持相应原生计算，还是走反量化后的兼容路径？

例如 NVIDIA Model Optimizer 和 LLM Compressor 都能参与低比特导出，但产物的格式与元数据约定可能不同。`compressed-tensors`、ModelOpt 配置以及 NVFP4/MXFP4 的具体 scheme，不能用一个随意的 `--quantization fp4` 概括。

### 8.2 用实际导出的目录加载

```python
from vllm import LLM

# 示例一：已经用 LLM Compressor 导出的 FP8 compressed-tensors 模型。
llm = LLM(model="./model-fp8-compressed", quantization="compressed-tensors")
```

```bash
# 示例二：已经按 ModelOpt NVFP4 格式导出的 checkpoint。
# 需要当前版本与 GPU 支持该格式；不是对原始模型现场执行 PTQ。
vllm serve ./model-nvfp4-modelopt --quantization modelopt_fp4
```

两段例子展示不同格式的加载方式，路径都必须替换为实际导出结果。MXFP4 也应从对应工具与模型的部署说明出发，不要只把字符串中的 `nv` 换成 `mx`。

### 8.3 质量门槛通过后，再看算力兑现

低比特越激进，越需要检查敏感层、校准任务和长输出。可以使用混合精度，让个别层保留更高精度，但要把它们的成本与兼容性记入结果。

性能上分别测 Prefill、不同 Batch 的 Decode、长上下文和多卡通信。如果 FP4 权重减小了，但 Kernel 回退、跨卡通信或 Attention 仍占主导，就不能期待原生矩阵乘法峰值直接成为服务收益。

💡 **提示**：本节给出数值格式与部署检查方法，不提供普适的“FP4 一定优于 INT4”结论。二者位宽接近，表示方式、缩放和 Kernel 都不同，应该在相同任务质量门槛下比较。

## 📝 总结

- 低比特浮点用指数适应多个数量级，但有效刻度仍有限。
- E4M3 与 E5M2 在尾数精度和动态范围之间取舍，特殊值规则要按具体变体核对。
- FP8 仍可能需要静态或动态 Scale，粒度与累加方式会影响质量。
- 原生 FP8 W8A8、Weight-only FP8 和 FP8 KV Cache 是不同路径。
- FP4 的 E2M1 点数很少，局部块缩放成为实际可用的关键。
- NVFP4 常用 16 元素块、FP8 块 Scale 加 FP32 张量 Scale；MXFP4 常用 32 元素块与 E8M0 Scale。
- 4-bit 数据还要计入 Scale 成本，完整格式也不能直接互换。
- 模型格式、框架 Kernel 与硬件指令必须对齐，再用质量与性能评测做选择。
