## 本章简介

当模型大到单张 GPU 装不下，或吞吐要求超过单卡上限时，就必须把推理拆到多卡甚至多机上。本章讲清推理场景下的并行策略——注意它与训练并行的目标不同：训练关注梯度同步与收敛，推理关注显存装载、TTFT/TPOT 延迟和吞吐。全程以 vLLM 的分布式能力为实例。

**张量并行（Tensor Parallel, TP）** 将每一层的权重矩阵按行/列切分到多卡，单次前向内部通过 AllReduce 聚合，可降低单卡权重占用；单请求延迟能否改善，要比较本地计算与通信总成本。本节分析 TP 的通信量、对 NVLink 带宽的依赖，以及节点内 TP、跨节点 TP 的链路取舍。

**流水线并行（Pipeline Parallel, PP）** 将模型按层切成多段放在不同 GPU 上，适合跨节点扩展；本节分析推理场景下 PP 的 Bubble 与 Micro-batch 组织，以及 TP×PP 的组合选择。

**数据并行与专家并行（DP / EP）** ：DP 复制多份引擎横向扩吞吐；EP 针对 MoE 模型将不同 Expert 分布到不同 GPU，通过 All-to-All 通信路由 Token，是部署超大 MoE 模型的关键。

**多节点部署（Ray 集群）** 讲清 vLLM 如何借助 Ray 编排多机多卡：集群拉起、Placement Group、TP/PP 在节点内外的映射，以及常见的通信与环境排错。

**vLLM 分布式部署实战** ：用 `tensor-parallel-size` / `pipeline-parallel-size` / `data-parallel-size` 部署大模型，验证多卡下的显存分布与吞吐提升。

## 新手怎样学习本章

### 先具备哪些基础

先理解 Token 是模型处理文本的基本单位，权重是已经训练好的参数，KV Cache 是生成过程中保留的历史状态。如果 Prefill、Decode、TTFT、TPOT 还不熟，可以先读 6.1 的术语和时间例子，再回来理解并行的目标。矩阵部分只需要跟着小数字计算，不要求先掌握分布式训练。

第一遍阅读时，围绕三个问题画图：**一条请求由谁计算？权重和 KV 放在哪里？设备之间传什么？** 这三个问题能把 TP、PP、DP、EP 从缩写变成具体的数据流。

### 按六步把概念接到部署

| 顺序 | 学完要能做什么 | 不依赖多卡的练习 |
|------|----------------|------------------|
| 6.1 总览 | 区分装不下、单请求慢与请求太多 | 算权重/KV 预算，画 GPU 分组 |
| 6.2 TP | 解释矩阵怎样分片、结果怎样合成 | 手算小矩阵，运行分片断言 |
| 6.3 PP | 解释层间接力、等待与气泡 | 画时间槽，运行流水线模拟器 |
| 6.4 DP/EP | 区分请求分流与 Token 找专家 | 比较长短请求，计算专家计数与加权输出 |
| 6.5 Ray | 区分资源编排与模型数据通信 | 画节点/进程图，判断 Pending 属于哪层问题 |
| 6.6 实战 | 按相同条件生成、压测并解释结果 | 读懂参数、设计实验记录；有 GPU 后再执行 |

### 怎样使用文中的公式与命令

先读公式前后的直觉解释，再跟着算例验证。文中标明“假设”的时间和容量只用于说明关系，不是实测成绩。Python 标准库小实验可以在普通 CPU 上学习；GPU 部署命令则需要实际硬件、兼容的软件环境与模型支持。

命令以 vLLM v0.19.0 为接口基线，使用 Linux Bash 语法；升级到其他版本时应重新核对参数。基础实验关闭前缀缓存以控制变量，MoE EP 则单独使用兼容的 MoE 模型，不与普通 Dense 模型的结果混在同一组比较。

## 📝 总结

- 用容量、延迟与吞吐区分并行目标，分别核算权重、KV 和运行时开销。
- TP、PP、DP 与 EP 的分工及组合要匹配真实互联与模型支持。
- 从进程放置到真实生成逐层验收，再用固定负载比较单位 GPU 收益。
