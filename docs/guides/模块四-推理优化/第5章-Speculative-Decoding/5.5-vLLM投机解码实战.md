这一节不以“服务能启动”为终点。我们要完成一条可复现闭环：固定版本 → 跑基线 → 开投机 → 发相同请求 → 读取接受指标 → 扫描并发与深度 → 决定是否上线。

命令按 vLLM 当前统一入口 `--speculative-config` 编写。投机解码演进很快，执行前请把安装版本与对应版本文档固定下来。

## 2. 先跑无投机基线

以 `Qwen/Qwen3-8B` 为演示 Target。请按实际显存替换模型或调整 `--max-model-len`。

```bash
vllm serve Qwen/Qwen3-8B \
  --host 0.0.0.0 \
  --port 8000 \
  --tensor-parallel-size 1 \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.85
```

```bash
curl http://localhost:8000/v1/models
curl http://localhost:8000/v1/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3-8B",
    "prompt": "Write a Python function that merges two sorted lists:\n",
    "temperature": 0,
    "max_tokens": 128
  }'
```

基线与投机组必须固定 revision、dtype、上下文上限、TP、Prompt、采样、输出长度、warmup、并发和到达率。

## 3. N-gram：零额外模型

N-gram 最适合先做冒烟实验，因为无需下载第二套权重：

```bash
vllm serve Qwen/Qwen3-8B \
  --host 0.0.0.0 \
  --port 8000 \
  --tensor-parallel-size 1 \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.85 \
  --speculative-config '{
    "method": "ngram",
    "num_speculative_tokens": 4,
    "prompt_lookup_min": 2,
    "prompt_lookup_max": 5
  }'
```

先扫描 `num_speculative_tokens=2/4/6`、min=2/3、max=4/5。随机字串几乎无重复，会低估 N-gram；应加入代码、RAG 引用和真实模板请求。

## 4. 独立 Draft Model

官方文档示例使用同家族的 Qwen 小模型：

```bash
vllm serve Qwen/Qwen3-4B-Thinking-2507 \
  --host 0.0.0.0 \
  --port 8000 \
  --seed 42 \
  --tensor-parallel-size 1 \
  --max-model-len 2048 \
  --gpu-memory-utilization 0.8 \
  --speculative-config '{
    "method": "draft_model",
    "model": "Qwen/Qwen3-0.6B",
    "num_speculative_tokens": 5
  }'
```

可在 JSON 中加入 `draft_tensor_parallel_size`、`max_model_len`、`parallel_drafting`。Target TP 在服务顶层；`tensor_parallel_size` 不是 `speculative_config` 合法 key。

### 4.1 异构词表

跨 Tokenizer 时可加 `"use_heterogeneous_vocab": true`。当前官方文档限定其使用 greedy Draft sampling，尚不支持概率式 Draft sampling。

## 5. EAGLE 与 EAGLE-3

EAGLE 权重必须与 Target 精确匹配，不能混用相似名称的基座版本。官方 EAGLE-3 配置形式：

```bash
vllm serve meta-llama/Meta-Llama-3.1-8B-Instruct \
  --tensor-parallel-size 2 \
  --speculative-config '{
    "method": "eagle3",
    "model": "RedHatAI/Llama-3.1-8B-Instruct-speculator.eagle3",
    "draft_tensor_parallel_size": 2,
    "num_speculative_tokens": 2
  }'
```

原始 EAGLE 对应 `"method":"eagle"`。`parallel_drafting: true` 可用于 EAGLE/Draft Model，但是否更快取决于后端。仓库认证失败时不要随意换成不匹配权重。

## 6. 原生 MTP

只有模型家族与 vLLM 都实现了兼容 MTP 时才可用。

官方在线示例：

```bash
vllm serve XiaomiMiMo/MiMo-7B-Base \
  --tensor-parallel-size 1 \
  --speculative-config '{
    "method": "mtp",
    "num_speculative_tokens": 1
  }'
```

某些模型另需 assistant checkpoint，通过 JSON 的 `model` 指定。先确认 checkpoint 与 vLLM 架构适配，从深度 1 开始，检查日志解析出的 method 和接受长度；超出训练深度可能报错或降低接受率。

## 7. 离线读取接受指标

vLLM 提供 `LLM.get_metrics()`。下面代码沿用官方离线示例中的指标定义：

```python
from vllm import LLM, SamplingParams

llm = LLM(
    model="Qwen/Qwen3-8B",
    speculative_config={"method": "ngram", "num_speculative_tokens": 4,
                        "prompt_lookup_min": 2, "prompt_lookup_max": 5},
)
llm.generate(["Schema: user_id, event_time. SQL: SELECT"],
             SamplingParams(temperature=0.0, max_tokens=128))
values, per_pos = {}, None
for metric in llm.get_metrics():
    if metric.name == "vllm:spec_decode_num_accepted_tokens_per_pos":
        per_pos = list(metric.values)
    elif metric.name.startswith("vllm:spec_decode_"):
        values[metric.name] = metric.value
drafts = values.get("vllm:spec_decode_num_drafts", 0)
draft_tokens = values.get("vllm:spec_decode_num_draft_tokens", 0)
accepted = values.get("vllm:spec_decode_num_accepted_tokens", 0)
print("AR:", accepted / draft_tokens if draft_tokens else 0)
print("Mean AL:", 1 + accepted / drafts if drafts else 1)
```

$$
\text{AR}=\frac{\text{accepted}}{\text{proposed}},\qquad
\text{Mean AL}=1+\frac{\text{accepted}}{\text{draft rounds}}
$$

Mean AL 中的 1 包括每轮最终至少由 Target 路径提交的 Token；不要把它与 AR 混用。

## 8. 在线压测与 Prometheus

### 8.1 固定形状跑一轮

服务启动后，在另一个终端执行：

```bash
vllm bench serve \
  --backend vllm \
  --model Qwen/Qwen3-8B \
  --host localhost \
  --port 8000 \
  --dataset-name random \
  --random-input-len 256 \
  --random-output-len 256 \
  --num-prompts 200 \
  --max-concurrency 8 \
  --request-rate inf \
  --ignore-eos \
  --seed 42
```

依次测试 `max-concurrency=1, 8, 32`，并对基线与每种投机配置使用相同 seed 和输入长度。

随机数据只用于控制长度。生产决策还应把 `--dataset-name` 换成业务数据或 ShareGPT，并提供 `--dataset-path`；不要把敏感 Prompt 复制到公共环境。

### 8.2 读取在线指标

vLLM OpenAI 服务暴露 `/metrics`：

```bash
curl -s http://localhost:8000/metrics \
  | rg 'vllm:spec_decode_(num_drafts|num_draft_tokens|num_accepted_tokens)'
```

Prometheus 中的接受率：

```promql
rate(vllm:spec_decode_num_accepted_tokens_total[5m])
/
rate(vllm:spec_decode_num_draft_tokens_total[5m])
```

平均接受长度：

```promql
1 + (
  rate(vllm:spec_decode_num_accepted_tokens_total[5m])
  /
  rate(vllm:spec_decode_num_drafts_total[5m])
)
```

Prometheus 客户端通常给 Counter 自动追加 `_total`；离线 `get_metrics()` 使用不带 `_total` 的内部名字。

### 8.3 结果记录模板

| 方法 | K | 并发 | AR | Mean AL | TTFT P95 | TPOT P95 | Output tok/s | 显存 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| baseline | 0 | 1 | - | 1.0 |  |  |  |  |
| ngram | 4 | 1 |  |  |  |  |  |  |
| draft | 3 | 1 |  |  |  |  |  |  |
| baseline | 0 | 32 | - | 1.0 |  |  |  |  |
| draft | 3 | 32 |  |  |  |  |  |  |

同一方法至少重复 3 次，报告中位数和波动，不要只保留最好的一次。

## 9. 调参与排错

### 9.1 四类常见问题

- **配置失败**：检查合法 JSON；`temperature` 不属于这里；Draft TP 键是 `draft_tensor_parallel_size`；EAGLE/MTP 必须匹配模型。
- **OOM**：依次降低上下文、并发、投机深度，或改用更小 Draft/N-gram；峰值动态 KV 比初始化更关键。
- **高接受却不快**：Draft、Verify、TP 通信或高并发已成为瓶颈；warmup 后扫描 \(K=1,2,3,5\)。
- **输出不同**：对齐 seed、temperature、top-p/top-k、stop 与模板；严格路径保持默认标准拒绝采样，区分分布一致与逐样本一致。

### 9.2 并行兼容

```bash
vllm serve --help=all | rg -i 'speculative|pipeline|draft'
```

再对照已安装版本的 incompatibility 小节；官方曾给出 PP 不兼容的明确版本范围，范围外不能靠旧博客推断。

## 10. 上线检查单

```text
[ ] vLLM、Torch、CUDA、Driver 和模型 revision 已记录
[ ] 使用 --speculative-config，而非 deprecated 分散参数
[ ] Baseline 与 Spec 使用相同采样和调度配置
[ ] 已 warmup，且每组重复至少 3 次
[ ] 覆盖真实代码/对话/RAG 负载，不只跑 random
[ ] 覆盖低并发和饱和并发
[ ] 记录 AR、Mean AL、TTFT、TPOT、tok/s 与显存
[ ] 检查长上下文与峰值并发 OOM
[ ] 检查 TP/PP/attention backend 的版本兼容
[ ] 设置收益回归门禁与快速回退到 baseline 的开关
```

一个保守启用策略是：先给代码补全或模板型流量单独开投机，观察一周，再扩大到接受率稳定的请求类别。不要一开始对所有流量“一刀切”。

## 📝 总结

- 当前 vLLM 使用统一 `--speculative-config` JSON；旧分散参数已 deprecated。
- N-gram 配置最轻，独立 Draft 需匹配模型与词表，EAGLE/EAGLE-3 需精确匹配专用权重，MTP 需模型原生支持。
- `num_speculative_tokens` 应从小值扫描；更深不保证更快。
- 离线可用 `LLM.get_metrics()` 读取 Draft、提案 Token 与接受 Token 计数。
- 在线可从 `/metrics` 读取 Prometheus Counter，计算 acceptance rate 与 mean acceptance length。
- 公平实验必须固定版本、请求、采样、warmup、并发和输出长度。
- 最终决策看真实负载下的 TPOT、goodput、尾延迟和显存，不看单独接受率。
