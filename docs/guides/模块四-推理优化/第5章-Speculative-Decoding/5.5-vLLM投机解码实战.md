## 2. v0.27.1 配置入口

CLI 使用：

```bash
--speculative-config '<合法 JSON 对象>'
```

Python 使用：

```python
LLM(
    model="...",
    speculative_config={
        "method": "...",
        "num_speculative_tokens": 3,
    },
)
```

旧式分散参数：

```text
--speculative-model
--num-speculative-tokens
...
```

已 deprecated，不应与新入口混用。

### 2.1 常用字段

| 字段 | v0.27.1 语义 |
|---|---|
| `method` | `draft_model`、`ngram`、`suffix`、`eagle`、`eagle3`、`mtp` 等 |
| `model` | Draft、EAGLE speculator 或 assistant checkpoint |
| `num_speculative_tokens` | 一轮投机 Token 上限/深度 |
| `draft_tensor_parallel_size` | Draft TP，只能为 1 或 Target TP |
| `max_model_len` | Draft 最大上下文 |
| `parallel_drafting` | 专门训练的并行 Draft/EAGLE 路径 |
| `use_heterogeneous_vocab` | Draft Model 的 TLI 异构词表 |
| `draft_sample_method` | `greedy` 或 `probabilistic` |
| `rejection_sample_method` | v0.27.1 源码默认 `standard`；另有 `synthetic`、`block` |
| `num_speculative_tokens_per_batch_size` | 按 batch 区间动态 K |

### 2.2 两个参数层级

Target TP 在顶层：

```bash
--tensor-parallel-size 2
```

Draft TP 在 JSON 内：

```json
{"draft_tensor_parallel_size": 2}
```

`tensor_parallel_size` 不是合法的用户侧 speculative config key；源码保留该名字主要用于提示误配。

采样参数也不在 speculative JSON 中：

```text
temperature / top_p / top_k
```

它们属于每次请求或 `SamplingParams`。

## 3. v0.27.1 支持矩阵

| 方法 | `method` | 是否需额外权重 | v0.27.1 关键约束 |
|---|---|---:|---|
| 独立 Draft | `draft_model` | 是 | 默认同词表；TLI 可异构词表 |
| PARD | `draft_model` | 是 | `parallel_drafting:true`，必须是专门训练的 PARD |
| N-gram | `ngram` | 否 | 配置 lookup min/max |
| Suffix | `suffix` | 否 | 需 `arctic-inference`，动态深度 |
| Medusa | `medusa` | 是 | SpeculativeConfig 接受；需匹配 speculator/model config |
| EAGLE | `eagle` | 是 | speculator 必须匹配 Target |
| EAGLE-3 | `eagle3` | 是 | 必须显式写 `method:"eagle3"` |
| MTP | `mtp` | checkpoint 内/assistant | 只支持已实现的模型家族 |

### 3.1 MTP 模型类型

v0.27.1 `MTPModelTypes` 源码包含：

```text
deepseek_mtp
mimo_mtp / mimo_v2_mtp
glm4_moe_mtp / glm4_moe_lite_mtp / glm_ocr_mtp
ernie_mtp
nemotron_h_mtp
exaone_moe_mtp / exaone4_5_mtp
qwen3_next_mtp / qwen3_5_mtp
longcat_flash_mtp
minimax_m3_mtp
bailing_hybrid_mtp
kimi_k3_mtp
pangu_ultra_moe_mtp
step3p5_mtp
hy_v3_mtp
gemma4_mtp
inkling_mtp
```

这是一份代码路径的模型类型列表，不是“任意同名 Hugging Face checkpoint 都保证可用”。仍要确认具体 checkpoint config、权重和 vLLM model implementation。

### 3.2 并行约束

v0.27.1 文档明确：

- `draft_tensor_parallel_size` 为 1 或 Target TP。
- 动态 K 主要测试于 EAGLE、EAGLE-3、DFlash。
- 动态 K 与 DP 不兼容；DP 下自动退回静态 K。
- 文档记录 PP 在 `vllm<=0.15.0` 不可组合。
- 文档记录 Draft Model 在 `vllm<=0.10.0` 不支持。

后两条是历史版本范围，不等于 0.27.1 的所有方法、模型、PP 组合都已充分验证。生产环境仍应跑冒烟和压力测试。

```bash

  --port "$PORT" \
  --seed 42 \
```

```bash
    "method": "ngram",
    "num_speculative_tokens": 4,
```

v0.27.1 中：

## 7. Suffix 配置

确认已安装：

```bash
python -c "import arctic_inference; print('arctic-inference ok')"
```

启动：

```bash
vllm serve "$TARGET" \
  --host 0.0.0.0 \
  --port "$PORT" \
  --seed 42 \
  --tensor-parallel-size 1 \
  --max-model-len 4096 \
  --gpu-memory-utilization 0.85 \
  --speculative-config '{
    "method": "suffix",
    "num_speculative_tokens": 16,
    "suffix_decoding_max_tree_depth": 24,
    "suffix_decoding_max_cached_requests": 0,
    "suffix_decoding_max_spec_factor": 1.0,
    "suffix_decoding_min_token_prob": 0.1
  }'
```

这里先将跨请求全局缓存设为 0：

```json
"suffix_decoding_max_cached_requests": 0
```

用于排除缓存热度和多租户数据问题。确认请求内收益后，再在隔离环境测试全局缓存。

`num_speculative_tokens` 是最大值；Suffix 会按匹配长度和概率动态选择实际深度。

## 8. 独立 Draft Model 配置

v0.27.1 官方示例使用 Qwen 同家族：

```bash
vllm serve Qwen/Qwen3-4B-Thinking-2507 \
  --host 0.0.0.0 \
  --port "$PORT" \
  --seed 42 \
  --tensor-parallel-size 1 \
  --max-model-len 2048 \
  --gpu-memory-utilization 0.80 \
  --speculative-config '{
    "method": "draft_model",
    "model": "Qwen/Qwen3-0.6B",
    "num_speculative_tokens": 5,
    "draft_tensor_parallel_size": 1,
    "max_model_len": 2048
  }'
```

不要因为两边都叫 Qwen 就跳过词表和模板检查。启动时检查最终日志：

```text
SpeculativeConfig(method='draft_model', ...)
```

并检查显存峰值和可用 KV blocks。

### 8.1 Probabilistic Draft

需要随机 Draft 时：

```json
{
  "method": "draft_model",
  "model": "Qwen/Qwen3-0.6B",
  "num_speculative_tokens": 3,
  "draft_sample_method": "probabilistic",
  "rejection_sample_method": "standard"
}
```

Probabilistic Draft 需要保留/使用完整 Draft 分布，显存成本高于默认 greedy。`standard` 才是本章严格输出分布实验的默认选择；`synthetic` 是研究/模拟路径，不能用于证明生产输出无损。

### 8.2 异构词表

```bash
vllm serve Qwen/Qwen3-8B \
  --gpu-memory-utilization 0.50 \
  --speculative-config '{
    "method": "draft_model",
    "model": "HuggingFaceTB/SmolLM2-135M-Instruct",
    "num_speculative_tokens": 3,
    "use_heterogeneous_vocab": true
  }'
```

v0.27.1 限制：

```text
method 必须是 draft_model
draft_sample_method 必须是 greedy（默认）
```

该示例用于验证 TLI 接口，不代表跨家族组合一定有正收益。

## 12. 动态 K

EAGLE-3 示例：

```bash
VLLM_USE_V2_MODEL_RUNNER=0 \
vllm serve meta-llama/Llama-3.1-8B-Instruct \
  --host 0.0.0.0 \
  --port "$PORT" \
  --speculative-config '{
    "method": "eagle3",
    "model": "yuhuili/EAGLE3-LLaMA3.1-Instruct-8B",
    "num_speculative_tokens": 5,
    "num_speculative_tokens_per_batch_size": [
      [1, 16, 5],
      [17, 32, 4],
      [33, 64, 3],
      [65, 128, 1],
      [129, 512, 0]
    ]
  }'
```

注意：

- 首段必须从 batch size 1 开始；区间包含端点且不能重叠。
- 区间之间的空隙和最后一段之后的 batch size 沿用前一段的 K。
- 全局 `num_speculative_tokens` 应覆盖最大 K。
- v0.27.1 文档示例设置 `VLLM_USE_V2_MODEL_RUNNER=0`。
- DP 下该 schedule 自动禁用。

先用静态 K 找每个 batch 区间的近似最优值，再配置 schedule；不要凭经验直接填。

## 14. Warmup 与重复

每次重启服务后：

1. 等待权重加载和 CUDA Graph 捕获完成。
2. 先发送与正式实验相同 shape 的 warmup。
3. 清楚 Prefix Cache 是冷还是热。
4. 正式组至少重复 3 次。
5. 报告中位数、P95/P99 和波动。

示例 warmup：

```bash
for i in 1 2 3 4 5; do
  curl -s "http://localhost:${PORT}/v1/completions" \
    -H "Content-Type: application/json" \
    -d "{
      \"model\":\"${TARGET}\",
      \"prompt\":\"Warmup request ${i}: explain speculative decoding.\",
      \"temperature\":0,
      \"max_tokens\":128
    }" >/dev/null
done
```

不要只保留最快一次。

## 15. 离线读取接受指标

v0.27.1 的官方离线示例通过 `LLM.get_metrics()` 读取 Counter 和 Vector：

```python
from vllm import LLM, SamplingParams
from vllm.v1.metrics.reader import Counter, Vector

llm = LLM(
    model="Qwen/Qwen3-8B",
    tensor_parallel_size=1,
    disable_log_stats=False,
    speculative_config={
        "method": "ngram",
        "num_speculative_tokens": 4,
        "prompt_lookup_min": 2,
        "prompt_lookup_max": 5,
    },
)

prompts = [
    "Schema: user_id, event_time, event_type. SQL: SELECT",
    "Complete this function:\ndef merge_sorted(a, b):\n",
]
params = SamplingParams(
    temperature=0.0,
    max_tokens=128,
)
outputs = llm.generate(prompts, params)

num_drafts = 0
num_draft_tokens = 0
num_accepted_tokens = 0
per_position = []

for metric in llm.get_metrics():
    if metric.name == "vllm:spec_decode_num_drafts":
        assert isinstance(metric, Counter)
        num_drafts += metric.value
    elif metric.name == "vllm:spec_decode_num_draft_tokens":
        assert isinstance(metric, Counter)
        num_draft_tokens += metric.value
    elif metric.name == "vllm:spec_decode_num_accepted_tokens":
        assert isinstance(metric, Counter)
        num_accepted_tokens += metric.value
    elif metric.name == "vllm:spec_decode_num_accepted_tokens_per_pos":
        assert isinstance(metric, Vector)
        if not per_position:
            per_position = [0] * len(metric.values)
        for i, value in enumerate(metric.values):
            per_position[i] += value

acceptance_rate = (
    num_accepted_tokens / num_draft_tokens
    if num_draft_tokens else 0.0
)
mean_acceptance_length = (
    1 + num_accepted_tokens / num_drafts
    if num_drafts else 1.0
)
survival = [
    value / num_drafts if num_drafts else 0.0
    for value in per_position
]

print("drafts:", num_drafts)
print("draft tokens:", num_draft_tokens)
print("accepted tokens:", num_accepted_tokens)
print("acceptance rate:", acceptance_rate)
print("mean acceptance length:", mean_acceptance_length)
print("per-position survival:", survival)
```

定义：

$$
\text{AR}
=\frac{\text{accepted draft tokens}}
{\text{proposed draft tokens}}
$$

$$
\text{Mean AL}
=1+
\frac{\text{accepted draft tokens}}
{\text{draft rounds}}
$$

逐位置 Vector 的第 \(i\) 项除以 `num_drafts`，得到“前 \(i+1\) 个候选全部存活”的无条件概率。

## 16. 在线 Prometheus 指标

OpenAI server 暴露：

```bash
curl -s "http://localhost:${PORT}/metrics" \
  | rg 'vllm:spec_decode_'
```

v0.27.1 创建三个 Counter：

```text
vllm:spec_decode_num_drafts
vllm:spec_decode_num_draft_tokens
vllm:spec_decode_num_accepted_tokens
```

以及带 `position` label 的：

```text
vllm:spec_decode_num_accepted_tokens_per_pos
```

Prometheus client 导出 Counter 时通常带 `_total`。

### 16.1 Acceptance Rate

```promql
sum(rate(vllm:spec_decode_num_accepted_tokens_total[5m]))
/
sum(rate(vllm:spec_decode_num_draft_tokens_total[5m]))
```

### 16.2 Mean Acceptance Length

```promql
1 + (
  sum(rate(vllm:spec_decode_num_accepted_tokens_total[5m]))
  /
  sum(rate(vllm:spec_decode_num_drafts_total[5m]))
)
```

v0.27.1 源码注释中的一处示例省略了 `num_drafts` 的 `_total`，但 Prometheus Counter 实际导出通常使用 `_total`；以你的 `/metrics` 文本为准。

### 16.3 逐位置存活率

```promql
sum by (position) (
  rate(vllm:spec_decode_num_accepted_tokens_per_pos_total[5m])
)
/
sum(rate(vllm:spec_decode_num_drafts_total[5m]))
```

若最后两位接近 0，应降低 K，再看 TPOT 是否改善。

## 18. 贪心正确性检查

同一服务配置分别跑 baseline 和 speculative，保存 Token IDs。OpenAI API 可请求 logprobs，但更直接的离线测试是使用 `LLM.generate` 并读取 `token_ids`。

概念脚本：

```python
from vllm import LLM, SamplingParams

PROMPTS = [
    "The capital of France is",
    "Write a Python binary search function:\n",
    "用三句话解释张量并行。",
]
PARAMS = SamplingParams(
    temperature=0.0,
    max_tokens=128,
    seed=42,
)

def run(speculative_config):
    llm = LLM(
        model="Qwen/Qwen3-8B",
        tensor_parallel_size=1,
        enforce_eager=True,
        speculative_config=speculative_config,
    )
    outputs = llm.generate(PROMPTS, PARAMS)
    return [list(o.outputs[0].token_ids) for o in outputs]

# 分两个独立进程运行，避免同时占用显存：
# baseline = run(None)
# spec = run({...})
# assert baseline == spec
```

实际应把两组结果写 JSON，再由第三个轻量脚本比较。使用独立进程还能避免模型对象销毁后显存未完全释放。

若不一致，先切到：

```text
batch=1
enforce_eager=True
temperature=0
无量化
短上下文
无 LoRA/grammar
```

逐项恢复，定位 shape、数值或功能交互。

## 19. 随机采样的输出分布检查

固定 seed 的单条文本不是正确统计量。对同一 Prompt 用不同 seed 重复采样。

### 19.1 采集

例如 baseline 和 speculative 各运行 10,000 次短输出，记录：

- 第一 Token ID；
- 前 2/3-gram；
- 输出长度；
- EOS；
- 任务分类结果。

### 19.2 第一 Token 频率

```python
from collections import Counter
import math

def tv_distance(a_ids, b_ids):
    a = Counter(a_ids)
    b = Counter(b_ids)
    na = len(a_ids)
    nb = len(b_ids)
    vocab = set(a) | set(b)
    return 0.5 * sum(
        abs(a[token] / na - b[token] / nb)
        for token in vocab
    )

def js_divergence(a_ids, b_ids, eps=1e-12):
    a = Counter(a_ids)
    b = Counter(b_ids)
    na = len(a_ids)
    nb = len(b_ids)
    vocab = set(a) | set(b)
    result = 0.0
    for token in vocab:
        p = a[token] / na
        q = b[token] / nb
        m = (p + q) / 2
        if p:
            result += 0.5 * p * math.log((p + eps) / (m + eps))
        if q:
            result += 0.5 * q * math.log((q + eps) / (m + eps))
    return result
```

### 19.3 统计解释

两个有限样本即使来自同一分布，TV/JS 也不会精确为 0。应：

1. 将 baseline 自己随机分成两半，得到自然波动。
2. 多次 bootstrap 置信区间。
3. 比较 baseline-vs-spec 偏差是否超过 baseline-vs-baseline。
4. 对多个 Prompt 和 temperature 重复。

### 19.4 必查的尾部行为

- EOS 比例；
- 输出长度分布；
- forbidden Token；
- structured output 解析成功率；
- top-p 边界附近 Token；
- 高温度长尾 Token。

投机理论无损不等于无需测试实现。

## 20. 性能归因

看到“更慢”时按顺序检查：

### 20.1 接受是否足够

```text
AR
Mean AL
per-position survival
```

若第一位存活就很低，先换 Proposer/领域或关闭。

### 20.2 Draft 是否太贵

比较 Drafted throughput、GPU trace 和 Draft TP collective。独立 Draft 可尝试：

- 更小 K；
- Draft TP=1；
- greedy Draft；
- 更小但匹配的 Draft；
- PARD/EAGLE。

### 20.3 Verify 是否 compute-bound

若低并发快、高并发慢，扫描 batch 并使用动态 K。不要继续优化 Draft 而忽略 Target Verify。

### 20.4 显存是否挤压容量

比较 baseline/spec：

- KV cache blocks；
- maximum concurrency；
- 峰值 reserved memory；
- OOM 请求形状。

## 21. 排障手册

### 21.1 JSON 解析失败

症状：

```text
invalid JSON / unexpected token
```

检查：

- shell 外层单引号；
- JSON 键和值双引号；
- 布尔值为 `true/false`；
- 无尾逗号。

先验证：

```bash
python - <<'PY'
import json
s = '''{
  "method": "ngram",
  "num_speculative_tokens": 4
}'''
print(json.loads(s))
PY
```

### 21.2 EAGLE 权重 shape 不匹配

检查：

- `method` 是否 `eagle3`；
- Target 是 Llama 3 还是 3.1；
- Base 还是 Instruct；
- speculator revision；
- hidden size。

不要通过忽略 missing/unexpected keys 强行启动。

### 21.3 MTP 被识别成 Draft

检查启动日志的：

```text
SpeculativeConfig(method=...)
```

Gemma 4 assistant 必须是 `mtp`。若版本不支持该路径，升级到正确版本，而不是改成 `draft_model`。

### 21.4 异构词表报错

检查：

```json
"method":"draft_model",
"use_heterogeneous_vocab":true,
"draft_sample_method":"greedy"
```

v0.27.1 不支持 TLI + probabilistic Draft。

### 21.5 OOM

按影响顺序尝试：

1. 降低 `num_speculative_tokens`。
2. 降低 `max_num_seqs`。
3. 降低 `max_model_len`。
4. 降低 `gpu_memory_utilization` 留动态空间。
5. 换更小 Draft 或 N-gram/Suffix。
6. 检查 Draft TP 和 CUDA Graph 预留。

不要只看启动成功，要跑“最长上下文 × 最大并发 × 最大 K”。

### 21.6 高接受但不快

常见原因：

- Draft 串行；
- Verify compute-bound；
- 高 batch；
- Draft TP 通信；
- 树节点多；
- metadata/KV 回收；
- Target 已量化得很快。

用 \(K=1/2/3/5\) 和 batch=1/8/32/饱和点定位。

### 21.7 输出不一致

先区分：

```text
贪心应一致却不一致
随机采样文本不同
随机采样分布显著不同
```

随机单样本不同通常不是缺陷。vLLM FAQ 明确不保证稳定 logprobs，batch expansion 和数值误差都可能改变输出。

### 21.8 指标没有出现

检查：

- 是否真的启用投机；
- 是否产生 Draft rounds；
- `disable_log_stats`；
- `/metrics` 是否来自正确端口；
- Counter 名是否带 `_total`；
- N-gram 是否长期未命中。

## 23. 原理—实现—实验—边界闭环

### 原理

投机只在：

$$
\frac{T_{\text{round}}}{\text{Mean AL}}
<
T_1
$$

时加速；严格采样还要求标准拒绝采样和正确的 Draft/Target 分布语义。

### 实现

v0.27.1 统一使用 `--speculative-config`。各方法的模型、TP、词表、依赖和动态深度约束不同，必须以 tag 文档、源码和启动日志三者核对。

### 实验

Baseline 与 Spec 只改变 speculative config；同时采集 bench 延迟、吞吐、Prometheus 接受指标、GPU/显存和输出分布。

### 边界

- EAGLE/MTP 权重必须匹配。
- TLI 只支持 greedy Draft。
- Suffix 需额外依赖和缓存治理。
- 动态 K 与 DP 不兼容。
- 固定 seed 文本不一致不等于分布错误。
- batch=1 加速不代表饱和 goodput 提升。

## 📝 总结

- 本节命令按 vLLM v0.27.1 核对，使用统一 `--speculative-config`。
- N-gram/Suffix 无第二套模型；Draft/PARD、EAGLE/EAGLE-3 和 MTP 各有不同权重与训练前置。
- `draft_tensor_parallel_size` 在 JSON 内，Target TP 在顶层。
- v0.27.1 标准正确性路径使用 `rejection_sample_method:"standard"`。
- 接受指标要同时看 AR、Mean AL 和逐位置存活率。
- 性能实验要覆盖低并发、固定到达率和饱和并发。
- 贪心用 Token ID 回归；随机采样用大量样本比较分布，而不是比较单条文本。
- 最终上线决策由 TPOT、TTFT、goodput、容量、显存和质量共同决定。
