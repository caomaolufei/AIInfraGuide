## 1. 三条迁移路线总览

| 路线 | 改动成本 | 与昇腾深度 | 适用场景 |
| --- | --- | --- | --- |
| **torch_npu 直迁** | 极低（cuda→npu） | 中（走适配层） | 存量 PyTorch 代码快速上昇腾 |
| **迁移到 MindSpore** | 中高（改写框架 API） | 高（原生深度适配） | 深度定制、追求极致性能 |
| **第三方框架适配** | 依框架而定 | 中 | HuggingFace 生态、vLLM 系等 |

**决策原则**：能直迁就直迁（成本最低），遇到性能或算子缺口再考虑深度改造。

## 2. 路线一：torch_npu 直接迁移

已在 2.4 详述，这里给一个「5 分钟迁移清单」：

1. `import torch_npu`；
2. 设备字符串 `cuda` → `npu`（`torch.npu.is_available()` 等）；
3. 分布式后端 `nccl` → `hccl`；
4. AMP：`torch.cuda.amp` → `torch.npu.amp`；
5. 专属 API：`torch.cuda.synchronize()` → `torch.npu.synchronize()` 等。

**验证标准**：跑通训练脚本，对比 loss 曲线与 GPU 环境是否一致、检查算子是否有 CPU 回退（性能骤降的隐患）。

## 3. 路线二：迁移到 MindSpore

适合「长期深耕昇腾」的场景。迁移要点：

- **API 映射**：MindSpore 提供 PyTorch API 映射表，`nn.Module→nn.Cell`、`forward→construct`、`DataLoader→Dataset` 等都有对应文档。
- **兼容层**：MindSpore 提供 PyTorch 兼容接口（如 `mindspore.torch`），部分代码可以直接跑，但深度特性仍有差异。
- **迁移工具**：MindSpore 社区提供模型转换/代码改写辅助工具，能自动完成一部分机械替换。
- **动态算子处理**：控制流（`if`/`for`）在静态图下需要适配（如使用 `ms.jit` 装饰器控制编译边界）。

**建议路径**：先小模型跑通迁移流程，再逐步迁移完整模型，逐算子核对结果。

## 4. 路线三：第三方框架适配生态

昇腾生态中，第三方框架的适配通常以「插件/后端」形式存在：

- **HuggingFace Transformers**：依托 torch_npu 直接可用（`model.to('npu')`），生态最顺滑。
- **vLLM（推理）**：通过 **vLLM-Ascend** 插件原生支持昇腾（详见第 6 章）。
- **PaddlePaddle 等**：官方提供昇腾适配版本或插件。
- **DeepSpeed / Megatron 类**：依赖 torch_npu 提供设备抽象，多数功能经 `cuda→npu` 替换可用。

**规律**：凡是建立在「PyTorch 设备抽象」上的第三方框架，昇腾（经 torch_npu）接住它们的成本都很低；直接依赖 CUDA 私有 API（如 custom kernel、CUDA graphs）的框架，需要额外适配。

## 5. 迁移评估与量化决策

迁移前先回答三个问题，别盲目动手：

1. **必要性**：为什么要迁到昇腾？算力缺口 / 合规 / 成本，目标要具体可量化。
2. **依赖清单**：代码依赖哪些 PyTorch/CUDA 特性？列一个「算子/API 依赖清单」，逐个核对昇腾支持矩阵。
3. **性能目标**：期望达到 GPU 环境的多少比例？用官方 Benchmark 与内部小规模测试先验证。

**迁移验收四件套**：

- 正确性：同种子下 loss/精度曲线与参考环境对齐；
- 性能：训练吞吐（samples/s）达到目标；
- 稳定性：长时间训练无 OOM、无随机挂掉；
- 可维护性：代码改动可控，后续升级链路清晰。

## 6. 大模型生态的迁移现状

大模型时代，迁移关注点集中在：

- **预训练/微调**：HF Transformers + torch_npu 即可；追求性能可迁移到 MindSpore 或保留 Megatron 风格代码 + hccl 后端。
- **推理部署**：vLLM-Ascend 提供 OpenAI 兼容服务（第 6 章），是当前昇腾大模型推理的主流入口。
- **量化与精度**：W8A8/AWQ/FP8 等在昇腾上的支持随 CANN 版本推进，迁移前先确认模型所需的量化方案是否可用。
- **工具链**：`msprof`（性能）、模型转换（ATC）、权重转换工具等，构成昇腾大模型开发的完整工具链。

**给团队的建议**：大模型迁移不要「一步到位」，先从「单卡跑通推理」→「小规模微调」→「分布式训练」→「生产部署」分阶段推进，每阶段都有明确的验收标准。

## 总结

- 三条路线：**torch_npu 直迁（成本最低）/ MindSpore 深度迁移 / 第三方框架插件**。
- 凡是走 PyTorch 设备抽象的框架，昇腾都能低成本接住；依赖 CUDA 私有 API 的才需要大改。
- 迁移前先量化评估（必要性、依赖清单、性能目标），迁移后按「正确性/性能/稳定性/可维护性」四件套验收。
- 大模型生态主线：**HF 训练 + vLLM-Ascend 推理 + MindSpore 深度优化**。
