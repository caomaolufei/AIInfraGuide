## 1. AscendCL 资源模型总览

AscendCL 的资源抽象非常收敛，核心只有几个概念：

| 概念 | 作用 | CUDA 对应物 |
| --- | --- | --- |
| Device | 一块昇腾逻辑设备（一张卡） | `cudaDevice` |
| Context | 设备上的上下文（进程内资源容器） | `CUcontext` |
| Stream | 按顺序执行的任务队列 | `cudaStream_t` |
| Event | 流内/流间的同步信号 | `cudaEvent_t` |
| 内存 | 设备内存（`aclrtMalloc` 分配） | `cudaMalloc` |

编程的基本节奏是固定的：

> **初始化（aclInit）→ 选设备（aclrtSetDevice）→ 建上下文/流 → 分配内存 → 搬数据 → 执行算子/核函数 → 同步 → 释放资源（aclrtFinalize）**

## 2. Device：先选设备

**Device 是昇腾物理/逻辑设备**，用 `aclrtSetDevice(device_id)` 指定当前进程使用哪张卡。多卡机器上，device_id 从 0 开始编号，对应 `npu-smi info` 里看到的 NPU 编号。

```cpp
// 使用设备 0
int32_t deviceId = 0;
aclrtSetDevice(deviceId);          // 设置当前设备
aclrtGetDevice(&deviceId);         // 查询当前设备
aclrtResetDevice(deviceId);        // 结束使用（应用退出前调用）
```

## 3. Context：设备的上下文

**Context（上下文）承载了进程在某张设备上的资源与状态**：内存分配、Stream、算子加载都在 Context 里管理。

- 昇腾的 Context 管理与 CUDA 略有差异：AscendCL 会为设备维护一个默认 Context，开发者多数情况下不需要显式创建，直接使用当前设备上的 Context 即可。
- 高级用法：`aclrtCreateContext` / `aclrtSetCurrentContext` / `aclrtDestroyContext` 用于精细管理多上下文场景（如多线程）。

一句话理解：**Context 是「设备上的资源作用域」，Stream 是「作用域里的任务队列」。**

## 4. Stream：任务的流水线

**Stream 是一条按顺序执行的任务队列**。同一 Stream 内的操作串行执行，不同 Stream 可以并行——这是昇腾实现「计算与搬运重叠」的基础设施。

```cpp
aclrtStream stream;
aclrtCreateStream(&stream);        // 创建流
// ... 下发算子/数据搬移任务 ...
aclrtSynchronizeStream(stream);    // 阻塞等待该流完成
aclrtDestroyStream(stream);        // 销毁流
```

和 CUDA 一样，**想隐藏内存搬运延迟，就用多条 Stream + 双缓冲**（第 3 章算子优化会用到）。

## 5. Event：任务之间的同步信号

**Event 用于记录 Stream 中某个点的完成状态**，实现流间同步：

```cpp
aclrtEvent event;
aclrtCreateEvent(&event);                 // 创建事件
aclrtRecordEvent(event, stream);          // 在流中记录一个"里程碑"
aclrtWaitEvent(event);                    // 等待该里程碑达成
aclrtSynchronizeEvent(event);             // 同步事件
aclrtDestroyEvent(event);
```

典型用法：让「搬移 Stream」和「计算 Stream」协作——搬完数据后 `aclrtRecordEvent`，计算流 `aclrtWaitEvent` 后再开始算。

## 6. 内存管理：aclrtMalloc 与内存拷贝

昇腾的设备内存用 `aclrtMalloc` 分配，用 `aclrtMemcpy` 在「设备↔设备」「主机↔设备」之间搬数据：

```cpp
void *devPtr = nullptr;
// 分配 1MB 设备内存
aclrtMalloc(&devPtr, 1024 * 1024, ACL_MEM_MALLOC_HUGE_FIRST);

// 设备内拷贝（dst, src, size, 方向）
aclrtMemcpy(devPtr, size, hostPtr, size, ACL_MEMCPY_HOST_TO_DEVICE);
aclrtMemcpy(hostPtr, size, devPtr, size, ACL_MEMCPY_DEVICE_TO_HOST);

aclrtFree(devPtr);                        // 释放
```

对照 CUDA：`cudaMalloc` → `aclrtMalloc`；`cudaMemcpy` → `aclrtMemcpy`。完全同构。

## 7. 最小可运行示例：AscendCL 生命周期

下面是一个「空转」最小程序，只做设备初始化与释放——但它是理解整个 AscendCL 生命周期的骨架：

```cpp
#include "acl/acl.h"
#include <cstdio>

int main() {
    // 1. 初始化（可传入配置路径，NULL 表示默认）
    aclError ret = aclInit(nullptr);
    if (ret != ACL_SUCCESS) {
        printf("aclInit failed: %d\n", ret);
        return -1;
    }

    // 2. 选择设备
    int32_t deviceId = 0;
    aclrtSetDevice(deviceId);

    // 3. 创建 Stream（默认 Context 已自动创建）
    aclrtStream stream;
    aclrtCreateStream(&stream);

    // 4. 分配内存（这里以 1MB 演示）
    void *devBuf = nullptr;
    aclrtMalloc(&devBuf, 1024 * 1024, ACL_MEM_MALLOC_HUGE_FIRST);

    // 5. ... 在此处下发数据搬移与算子执行（见 2.3）...

    // 6. 同步并清理
    aclrtSynchronizeStream(stream);
    aclrtFree(devBuf);
    aclrtDestroyStream(stream);
    aclrtResetDevice(deviceId);
    aclFinalize();      // 释放 AscendCL 全局资源
    return 0;
}
```

编译要点：

```bash
# 假设 CANN 安装路径为 /usr/local/Ascend/ascend-toolkit/latest
g++ -o acl_demo acl_demo.cpp \
    -I /usr/local/Ascend/ascend-toolkit/latest/include \
    -L /usr/local/Ascend/ascend-toolkit/latest/lib64 \
    -lascendcl
```

运行前记得 `source set_env.sh`（CANN 环境脚本），确保 LD_LIBRARY_PATH 指向 CANN 的 `lib64` 与 `driver` 目录。

## 8. 与 CUDA 编程模型的对照

| 步骤 | CUDA | AscendCL |
| --- | --- | --- |
| 初始化运行时 | `cudaSetDevice` | `aclInit` + `aclrtSetDevice` |
| 建上下文 | `cuCtxCreate` | `aclrtCreateContext`（默认 Context 已可用） |
| 建流 | `cudaStreamCreate` | `aclrtCreateStream` |
| 分配内存 | `cudaMalloc` | `aclrtMalloc` |
| 内存拷贝 | `cudaMemcpy` | `aclrtMemcpy` |
| 下发计算 | `kernel<<<...>>>` | `aclnnXxx(...)`（下一章） |
| 同步 | `cudaStreamSynchronize` | `aclrtSynchronizeStream` |
| 释放 | `cudaFree` / `cudaDeviceReset` | `aclrtFree` / `aclrtResetDevice` + `aclFinalize` |

**结论**：如果你写过 CUDA，AscendCL 可以在 1 小时内上手。真正的差异不在资源管理，而在「算子怎么调用」——那是下一章 aclnn 的主题。

## 总结

- AscendCL 资源模型 = Device + Context + Stream + Event + 设备内存，与 CUDA 一一对应。
- 标准生命周期：**aclInit → SetDevice → CreateStream → Malloc/Memcpy → 执行 → Sync → Free → Finalize**。
- Stream 是实现「搬运/计算重叠」的关键基础设施，多 Stream + Event 可构建流水线。
- 编译需链接 `libascendcl`，运行前必须 source CANN 环境脚本。
